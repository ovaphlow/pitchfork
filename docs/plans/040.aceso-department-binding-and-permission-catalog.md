## 1. 背景：QA 提出的三条

1. **部门 ↔ 用户断链**：039 已解决（`subject_departments` + 用户页部门列/弹窗 + 部门页成员数），
   仅「负责人」字段未做，产品已决定本轮不做。
2. **部门 ↔ 业务断链**：成立。`RequisitionsSection.tsx:469` 的「申领科室」是自由文本，
   `RequisitionService.kt:722` 只校验非空；申领科室与部门主数据零关联、零校验。
3. **权限码只写不读**：部分成立。`nursing:execute` 已接在 `/nursing/v1/*` 两条写路由（037/038），
   但（a）写入端零校验，中文/`12345` 照收（`roles/mod.rs` 只 trim+去重）；
   （b）前端只有角色页与用户页读权限码；（c）覆盖只有一个模块。

## 2. 设计决策

### D1 — 申领科室绑定部门 code，不建外键（跨服务无法建）

- 申领表在 Aceso PostgreSQL（`libs/pharmacy`，V300+），部门表在 Nexus SQLite；数据库层无法建外键。
- 因此申领表继续存文本 `department`，语义改为 `departments.code`（039 已保证 code 创建后不可改，可作稳定键）。
- Aceso 侧新增 `DepartmentDirectory` 端口（Nexus 支撑），创建/更新申领时校验 code 存在，不存在返回 400。
- 前端换成下拉，选项来自 `listDepartments()`；列表/详情显示部门名称（code→name 映射），
  历史自由文本值原样展示、不阻断查看。

### D2 — 权限码：产品声明目录，Nexus 只校验格式

- 「有哪些码可用」由产品声明：把 `DeclaredPermissions.kt` 从「已接线路由表」扩成权限目录
  （`code + 中文说明 + routes`），自省端点返回目录并标注 `wired: true|false`。
- 保留「未接线也可建角色」的能力：放量协议要求先建角色再接线，清单不能只含已接线的码。
- Nexus 侧补格式校验 `^[a-z][a-z0-9_]*:[a-z][a-z0-9_]*$`：挡住中文、纯数字、`totally.made.up:code`（域含点）。
- 仍保留「目录里出现别的产品的码不报错」（037 D4）：共享目录允许未知码，UI 靠目录收敛输入。

### D3 — 角色页权限码改为按域分组的多选清单

- 选项来自自省目录，条目显示「权限码 · 说明 · 未接线」。
- 不再提供自由文本输入，从源头杜绝 `totally.made.up:code`、中文、`12345`。
- 自省端点不可用时退回只读提示，不允许盲填（避免又写出垃圾）。

### D4 — 覆盖扩展只做发药确认，账单留待路径级门禁设计

- 发药确认 `POST /pharmacy/v1/dispenses/:id/confirm` 到 `pharmacy:dispense`，逐路由挂门禁。
- 账单写操作位于 `/healthcare/v1/*` 前缀下，整段挂门禁会误伤非账单路由，需要路径级门禁设计，
  单独立项，不并入本轮。
- **放量协议（必须）**：接线前目录里要有 `pharmacy.staff`（`pharmacy:dispense`）且已分配给真实账号，
  否则接线当刻发药确认对所有人 403。

### D5 — 前端权限感知不做

- 侧边栏按权限过滤、按钮置灰本轮不做（产品 2026-10-02 裁定）。后端 403 仍是唯一边界。

## 3. 接口契约（冻结）

```text
GET /crate-api/access/v1/permissions                 （Aceso，需登录）
  → 200 { "permission_codes": ["nursing:execute", "pharmacy:dispense"],
          "catalog": [ { "code": "pharmacy:dispense", "description": "发药确认",
                         "wired": true,
                         "routes": [ {"method":"POST","path":"/pharmacy/v1/dispenses/:id/confirm"} ] },
                       { "code": "billing:write", "description": "账单写操作",
                         "wired": false, "routes": [] } ],
          "routes": [ {"method","path","permission_code"} ] }
  （`routes` 保持 037/038 既有形状不变；`permission_codes` 改为"目录全集"而非"已接线集合"）

POST /crate-api/pharmacy/v1/requisitions              body.department = 部门 code
  → 400 unknown department；→ 201/200 既有行为不变
PUT  /crate-api/pharmacy/v1/requisitions/:id/approve|dispense   既有行为不变
```

不变式：申领的路由、状态机、幂等键、库存联动全部不变；`department` 只是从"任意非空文本"收紧为"必须是目录里的 code"。

## 4. 验收口径

1. **申领科室受控**：用不存在的 code 建申领 → 400；用目录里的 code → 成功且回读一致；历史自由文本行仍可查看。
2. **权限码格式**：`totally.made.up:code`、`中文码`、`12345` 在 Nexus 侧被拒（400）；`nursing:execute` 不受影响。
3. **目录可见**：角色页权限码只能从清单勾选；未接线码显示「未接线」；自省端点拿不到时不提供输入。
4. **发药接线**：有 `pharmacy:dispense` → 放行到业务逻辑；无 → 403 + `required_permission`；上游故障 → 503。
5. **回归**：`:apps:aceso:test`、`:libs:pharmacy:test`、`cargo test`、`pnpm --filter @pitchfork/aceso build` 全绿。

## 5. 范围与明确不做

- 不做侧边栏/按钮级权限过滤（D5）、不做部门负责人。
- 不把 `beds/encounters.department`（照护单元/病区）挂到部门目录（039 D6）。
- 不改账单路由的门禁（D4）。
- 不在库里做旧自由文本的强制迁移；只在写入端收紧。
