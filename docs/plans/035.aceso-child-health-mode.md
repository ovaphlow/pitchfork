## 1. 背景与问题定性

用户实测：儿保模式的**文案**已经改成「儿童」（儿童健康档案 / 建立儿童基础档案 / 录入儿童 / 儿童健康档案列表），但**数据模型与表单没有变**：

- 儿保列表里躺着 1950 年、1965 年生的两位「儿童」——它们是既有养老/医疗患者，被原样列进儿童档案；
- 录入表单字段与长者完全一样（姓名/性别/出生日期/身份证号/住院号/医保信息/过敏史/既往病史）；
- 没有监护人、出生体重、月龄、预防接种等儿保字段。

**定性**：`ui-astro/apps/aceso/src/lib/domain.ts` 的 `DOMAIN_ENTITY`（域词表单一事实来源）只切换了名词与页面标题；产品域只存在于 `localStorage["aceso-domain"]`，服务端没有任何「域」概念，`patients` 是医疗/养老/儿保共用的通用主表，也没有儿童标识与儿保字段。**本轮要把「里子」补上**：儿保档案在数据层可识别、可过滤，儿保专属字段可录入、可回显、可校验。

## 3. 设计决策（本计划推荐口径，确认即冻结）

### D1 — 儿保档案标识：显式 `person_type` 列（推荐）

新增 `healthcare.patients.person_type VARCHAR NOT NULL DEFAULT '居民'`，取值与前端 `DOMAIN_ENTITY.person` 对齐：`居民` / `长者` / `儿童`。

- 建档时由前端按当前域写入（医疗→居民、养老→长者、儿保→儿童）；服务端白名单校验。
- 儿保档案列表请求带 `person_type=儿童`，**只显示儿童**；1950/1965 两位既有记录默认 `居民`，自然退出儿保列表，**无需回填、不改写历史数据**。
- 医疗/养老列表**保持不过滤**（现状）：既有数据默认 `居民`，若养老模式改为只显示 `长者` 会把真实长者全部隐藏，故不做对称过滤。

备选（不推荐）：按 `birth_date` 年龄推导。缺点：`birth_date` 可空、儿童/成人边界需产品定义、无法回答「这条档案属于哪个产品域」，仍不能解决「数据模型没变」。

### D2 — 儿保专属字段：新增 `child_health_profiles` 表（推荐）

新增 1:1 子表，`patient_id` 唯一外键：

| 列 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(32) PK | ULID |
| patient_id | VARCHAR(32) NOT NULL UNIQUE REFERENCES patients(id) | 1:1 |
| guardian_name | VARCHAR | 监护人姓名 |
| guardian_relationship | VARCHAR | 与儿童关系 |
| guardian_phone | VARCHAR | 监护人电话 |
| birth_weight_g | INTEGER | 出生体重（克） |
| birth_height_mm | INTEGER | 出生身长（毫米） |
| delivery_mode | VARCHAR | 分娩方式（顺产/剖宫产/…，应用层白名单） |
| feeding_method | VARCHAR | 喂养方式（母乳/混合/人工，应用层白名单） |
| vaccination_summary | TEXT | 预防接种摘要 |
| vaccination_records | JSONB DEFAULT '[]' | `[{vaccine,dose,date,facility}]` 结构化接种记录 |
| remark | TEXT | 备注 |
| metadata | JSONB | 扩展位 |
| created_at / updated_at | TIMESTAMPTZ | 时间戳 |

理由：直接回应「数据模型没变」，服务端可校验、列表可直接取监护人，为后续生长发育/接种排程留扩展位。备选 `patients.metadata` 不推荐：无类型、无校验、列表要解析 JSON，问题依旧。

### D3 — 月龄为派生值，不落库

新增前端纯函数 `formatAge(birthDate, now)`：<1 月显示「N 天」，<24 月显示「N 月」，≥24 月显示「N 岁 M 月」。与 `datetime.ts` 同口径（显式 `Asia/Shanghai` 业务时区或纯日期差），单测锁定边界。

### D4 — 儿保建档 `birth_date` 必填（推荐）

`person_type=儿童` 时服务端要求 `birth_date` 非空，否则 400 中文提示；本轮**不设年龄上限硬校验**（仅列表显示月龄，便于人工识别异常记录）。是否硬限制年龄由产品裁定。

### D5 — 预防接种本轮范围：结构化摘要 + 记录列表

仅落 `vaccination_summary` + `vaccination_records` JSONB，**不做**疫苗目录、月龄排程、到期提醒（后续独立计划）。

### D6 — 历史数据不回填

不改写既有患者；儿保列表通过 `person_type=儿童` 排除非儿童。是否提供「转为儿童档案」入口，本轮不做（后续按需）。

## 4. 数据模型（V525）

`service-vertx-kotlin/libs/healthcare/src/main/resources/db/migration/V525__add_person_type_and_child_health_profiles.sql`：

```sql
CREATE SCHEMA IF NOT EXISTS healthcare;
SET search_path TO healthcare, public;

ALTER TABLE healthcare.patients
    ADD COLUMN person_type VARCHAR NOT NULL DEFAULT '居民';
CREATE INDEX idx_patients_person_type ON healthcare.patients(person_type);

CREATE TABLE healthcare.child_health_profiles (
    id                   VARCHAR(32) PRIMARY KEY,
    patient_id           VARCHAR(32) NOT NULL UNIQUE REFERENCES healthcare.patients(id),
    guardian_name        VARCHAR,
    guardian_relationship VARCHAR,
    guardian_phone       VARCHAR,
    birth_weight_g       INTEGER,
    birth_height_mm      INTEGER,
    delivery_mode        VARCHAR,
    feeding_method       VARCHAR,
    vaccination_summary  TEXT,
    vaccination_records  JSONB DEFAULT '[]',
    remark               TEXT,
    metadata             JSONB,
    created_at           TIMESTAMPTZ DEFAULT now(),
    updated_at           TIMESTAMPTZ DEFAULT now()
);
```

- 不新增 CHECK 约束（沿用「枚举由应用层白名单管控」的既有范式，见 V500/V508）。
- 不回填、不删列、不改既有列语义；`id_card_no` 仍可空且唯一（儿童可不填）。
- 不重跑 jOOQ codegen：`patients.person_type` 与 `child_health_profiles` 一律用 `DSL.field(DSL.name(...))` / `DSL.table(DSL.name("healthcare","child_health_profiles"))` 按名引用（与 V523/V524 一致）。SELECT 用带表名限定、UPDATE SET 用裸列名。

## 5. 接口契约（冻结，车道不得改）

`/crate-api/healthcare/v1`：

- `POST /patients`：请求体新增
  - `person_type?: "居民"|"长者"|"儿童"`（缺省 `居民`；非法值 400）
  - `child_profile?: { guardian_name?, guardian_relationship?, guardian_phone?, birth_weight_g?, birth_height_mm?, delivery_mode?, feeding_method?, vaccination_summary?, vaccination_records?, remark? }`（仅 `person_type=儿童` 时持久化）
  - 约束：`person_type=儿童` 且缺 `birth_date` → 400；`child_profile` 传了但 `person_type≠儿童` → 400。
  - 响应：`Patient`（含 `person_type`、`child_profile`）。
- `PUT /patients/:id`：新增 `person_type`、`child_profile`（存在即 upsert，`null` 表示清空可选字段；语义与既有部分更新一致）。`child_profile` 与 `person_type=儿童` 的约束同创建。
- `GET /patients?person_type=儿童`：新增过滤参数（与 `name`/`status` 叠加）。
- `GET /patients/:id`：响应内嵌 `child_profile`（非儿童为 `null`）。
- 列表响应保持 `{records, meta:{total}}`；错误保持 `{error}`。

`packages/shared/src/aceso.ts`：

- `Patient` 增加 `person_type: string`、`child_profile: ChildHealthProfile | null`。
- `PatientInput` 增加 `person_type?`、`child_profile?`。
- 新增 `ChildHealthProfile` 接口；`listPatients` 参数增加 `person_type?`。

## 6. 前端行为

- `lib/domain.ts`：`DOMAIN_ENTITY` 增加 `personType` 派生（`person` 即 `person_type` 值），并导出域→`person_type` 映射，避免组件硬编码。
- `components/EldersPage.tsx`：
  - 列表：域为 `儿保` 时请求 `person_type=儿童`；列改为 姓名/性别/出生日期/**月龄**/**监护人**/联系电话/状态/操作（儿保域隐藏「身份证号/住院号」列；医疗/养老列不变）。
  - 表单：域为 `儿保` 时渲染儿保字段分组——基本信息（姓名/性别/出生日期/身份证号）＋监护人（姓名/关系/电话）＋出生信息（出生体重/出生身长/分娩方式）＋喂养与接种（喂养方式/预防接种摘要/接种记录/备注）；医疗/养老表单不变。
  - 保存时按当前域写入 `person_type` 与 `child_profile`；编辑时回显。
- `lib/age.ts`（新增）：`formatAge` 纯函数。
- `tests/age.test.ts`（新增，`node:test`）：锁定 <1 月/1–23 月/≥24 月边界与跨时区无关性。

## 9. 验收口径

1. **列表归位**：儿保模式下「儿童健康档案」列表只显示 `person_type=儿童`；`person_type=居民`（含 1950/1965 两位既有记录）不出现；分页 `meta.total` 与过滤后一致。
2. **字段落位**：儿保录入表单包含 D2 全部字段，可保存、重新打开可回显、可编辑更新；列表儿保域显示「月龄」「监护人」列。
3. **月龄正确**：`formatAge` 边界——出生当天=0 天级、1 个月=1 月、23 月=23 月、24 月=2 岁 0 月；结果与主机时区无关。
4. **服务端校验**：非法 `person_type` 400；`person_type=儿童` 缺 `birth_date` 400；`child_profile` 配非儿童 400；错误体为 `{error}`。
5. **回归**：医疗/养老模式的列表、表单行为与现状一致（仅新增 `person_type` 透传）；`domain-labels.test.ts`、`datetime.test.ts`、`age.test.ts` 全绿；`pnpm --filter @pitchfork/aceso build` 0 error；`./gradlew :libs:healthcare:test` 全绿。
6. **真库**：`ChildHealthProfileIntegrationTest` 覆盖创建/列表过滤/回显/更新/校验拒绝，且测试结束 fixture 残差为 0。
