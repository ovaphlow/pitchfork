## 7. 验收口径（逐项）

- **W1**：真实库（`aceso_test`）中构造「老人 → 在住入住 → 用药医嘱（已护士核对）→ 护理任务/执行 → 从医嘱发药 → DISPENSED（扣库存）」
  后，`GET /crate-api/nursing/v1/executions/{id}/administration/sources` 返回 ≥1 条含 `remaining_quantity > 0` 的记录；
  随后 `POST .../administration`（`result=已服`，数量 ≤ 剩余）返回 201 且执行变 `COMPLETED`。
  若复现证明「原本就查得到」，则必须先给出反例说明（同一 fixture 下接口确实返回空）再改代码。
- **W2**：`result=拒服`（带 reason）返回 201，执行变 `SKIPPED`，不再出现 500；
  对终态执行重复提交返回 409，且前端显示中文可读文案，不再出现英文原文或 `{"error":"internal error"}` 裸露。
- **W3**：`admit_date = 2026-08-06T16:00Z` 的入住，生成 8 月账单区间为 `2026-08-07 ~ 2026-08-31`（**25 天**；修复前的错误值是 08-06~08-31 = 26 天），
  与入住管理/医生诊疗页面显示一致；`period_start/period_end` 与天数同口径。
  （口径更正：原计划误写 26 天，L2 实现按既有 `BillingEngine.inclusiveDays` 口径产出 25 天，本处已修正。）
- **W4**：机构时区当天为 2026-09 时，`month=2026-10` 的生成请求返回 400（稳定文案），
  precheck 对该月返回 `can_generate=false` 且 `blocked_by` 可被前端映射；`2026-09`、`2026-08` 仍可生成。
- **W5**：当月账单已存在时，「生成账单」按钮仍可用；弹窗内可切换账期，
  对不可生成账期给出中文原因与该账期专属 CTA（不再出现与配置无关的「去配置费用项目」）。
- **W6**：押金台账「操作人」列显示主体姓名（目录未命中时才回退 ID 或 `-`）。
- **W7**（按「不能推导时的兜底」验收）：发药弹窗保留 `1`，但必须显示医嘱频次/疗程提示并说明「系统不做自动换算」，
  避免药师在无信息情况下少发；自动预填属后端契约扩展，不在本期。
- **W8**：用户可见文案不再出现 `029`、`030` 等内部计划编号。
- **W9**：医嘱/执行列表的列名与内容语义一致（正文列不再叫「任务」；护理任务列与医嘱正文列可区分）。
- **W10**：给出 `SESSION_IDLE_TTL=30m` 是否因未续期导致掉线的判断，附代码位置与最小验证建议；不改行为。
- **通用**：`git diff main...HEAD --stat` 不含迁移、不含 `packages/shared` 契约变更（除必要类型外不得改客户端契约）。
