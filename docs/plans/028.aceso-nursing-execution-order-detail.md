## 3. 设计要点

1. **JOIN 与列歧义**：`medical_orders` 与 `nursing_tasks` 共有 `id/status/metadata/created_at/encounter_id`，
   未限定列名在 PG 会报 `column reference is ambiguous`。因此
   - `TaskService` 读路径给任务表起别名 `nt`、医嘱表 `mo`，`WHERE`/`ORDER BY` 全部用
     `DSL.field("nt.列名", …)` 限定（别名表的 `Table.field(String)` 在 jOOQ 3.19 返回可空，
     故不使用）；计数查询保持原样（未限定列、无 JOIN），行数与 SQL 语义不变。渲染结果：
     `select "nt".*, mo.order_details as "order_details", mo.order_type as "order_type" from "nursing"."nursing_tasks" as "nt" left outer join "healthcare"."medical_orders" as "mo" on nt.order_item_id = mo.id …`
   - **合并后（main 抽出的公共片段）**：两列加进 `executionProjectionColumns()`，
     `LEFT JOIN healthcare.medical_orders mo ON t.order_item_id = mo.id` 加进
     `executionRowsQuery()`——即 `/today` 的 total / status_totals+overdue_total_all 聚合 /
     overdue_total / 列表与 `/overdue` 的 total / 列表**六条 SQL 共用同一 FROM/JOIN**
     （main 的既有约定：两个入口禁止各自复制查询）。
     口径：JOIN 落在 `medical_orders.id`（V500 已确认是 PRIMARY KEY）上，至多 1:1，
     因此计数/聚合行数不变。副作用是 `/overdue` 列表也带出两字段——这是期望行为
     （护士在跨日逾期队列里同样要看到药名），逾期队列与今日看板共用 `todayColumns`，新列自动生效。
   - `MedicationAdministrationService` 的 `listAdministrations`（baseFrom）与 `readAdministration`
     加同一 LEFT JOIN；其 COUNT 查询不变；条件/排序本就全部带 `ma.`/`p.` 限定，无歧义。
2. **形状一致与守卫（实现方式在合并后调整，见 §9 D3）**：`TaskService.toJson` 拆成
   `toJson(row)`（非 JOIN 路径，恒返回 `order_details: null` / `order_type: null`）与
   `toJson(row, withBoundOrder: Boolean)`；只有带 JOIN 的 `list`/`get` 传
   `withBoundOrder = true`。这样非 JOIN 路径**完全不碰这两列**，既不依赖
   `Row.getColumnIndex` 这类驱动实现细节，也不会因为 mock 行/其它驱动而炸。
   采用显式开关的直接原因：最初的 `getColumnIndex(...) >= 0` 探测写法在合并后导致
   `libs:healthcare:test` 16 条用例失败（healthcare 的 mock Row 未实现 `getColumnIndex`
   → `MockKException: no answer found for Row.getColumnIndex(order_details)`）；
   改开关后 healthcare 541/0/0 恢复全绿，且无需改动 `libs/healthcare` 任何文件。
   守卫由 §6.1 的「严格行桩」用例锁死（桩不实现 `getColumnIndex`，且取缺失列时抛
   `NoSuchElementException`；把非 JOIN 路径改成读取两列，用例必红）。
3. **展示推导唯一化**：`formatOrderItemLabel(orderType, orderDetails)` 为医生页与护理页共用；
   MEDICATION 生成 `药名 剂量 单位 途径`（空值跳过，药名优先 `drug_name`，缺失退回
   `material_name`），其它类型只显示主明细字段，无可用明细返回 `null`。
