## 1. 背景与目标

052 交付后，护士日常链（测量/成长/接种/异常通报/指导）已闭环，但**医生侧仍缺三块日常能力与三项优先功能**：

| 用户诉求 | 现状 | 缺口定性 |
|---|---|---|
| 体检诊断 | `child_health_checkups`（V526）只有 `items/conclusion`，无诊断字段 | **无法记录医生诊断** |
| 发育评估 | 无任何量表/评分能力（全库无 scale/screening/发育） | **缺核心决策支持** |
| 健康问题 Referral 与转诊 | 仅 `vital-signs/:id/refer`（体征异常→随访）；体检 `conclusion=需转诊` 无落地动作 | **无健康问题转诊记录** |
| 疾病防控指导 | `ChildGuidanceService` 有「疾病预防」主题（护士日常口径） | 缺医生**疾病防控**指令/记录 |
| ★ 发育迟缓筛查量表与结果记录 | 无 | **核心决策支持** |
| ★ 健康体检报告生成与导出 | 无 | **数据产出** |
| ★ 药物过敏史与 contraindication 提醒 | `patients.allergies` 仅存不查；`DrugCatalogPort` 只校验药品存在，**不做过敏/禁忌检查** | **安全边界** |

**目标**：在儿保域补齐医生「体检诊断 → 发育评估/筛查 → 转诊 → 疾病防控指导 → 报告产出」的日常链，并在开嘱链路上加**药物过敏与禁忌提醒**安全边界；全部写入受既有权限码管辖（`clinical:write` / `health:manage`），新增迁移 V531+，持久化按 AGENTS 默认走**原生参数化 SQL**。

## 3. 总体设计决策

### Da — 医生写操作复用 `clinical:write`，护士相邻录入保留 `health:manage`

| 动作 | 权限码 | 理由 |
|---|---|---|
| 筛查**录入/执行**（量表答题与计分落库） | `health:manage` | 筛查可护士执行，与 052 记录口径一致 |
| 筛查**判读/结论/转诊**、体检**诊断**、**转诊**、**疾病防控指导** | `clinical:write` | 临床判断与指令，复用 046 既有码（048 D1 同思路） |
| 报告**生成/导出**、过敏**查询** | 读开放（046 D7） | 首屏读；PHI 见 Dd |

不新增权限码；所有新增写路由登记进 `DECLARED_PERMISSIONS`（集中式），读路由不上门禁。**权限拆分（筛查录入 vs 判读）见 §11 待裁定**。

### Db — 发育筛查：量表定义与评分引擎先独立、后持久化

把「评分引擎（纯逻辑）」与「结果持久化（DB）」拆成两个任务（A1/A2），使核心决策支持逻辑可在**无数据库**下先测透，再接表。量表定义采用**声明式量表包**（`scale_code/version/domains/items/月龄分档/切点` + 计分规则），引擎按儿童月龄选择适龄条目并计算 领域分 → 总分 → 判读（正常/可疑/异常）。**量表版权需产品裁定**（§11 Q1），本计划只交付引擎与一个占位量表包，不预置受版权保护的量表内容。

### Dc — 体检诊断：扩展 `child_health_checkups`，不改 `diagnoses` 限制

在 `child_health_checkups` 增加医生回写字段（`diagnosis`/`diagnosis_code`/`reviewed_by`/`reviewed_at`/`status`），**不**放宽 `diagnoses` 的 `ELDERLY_CARE` 限制（放宽会波及养老/医疗域回归）。理由：052 已确立「儿保体检独立于 encounter」的口径，医生诊断挂在体检记录上最小、最稳。备选（为儿童建 `CHILD_HEALTH` encounter 以复用 `diagnoses` 表）见 §11 Q2。

### Dd — 转诊：独立 `child_referrals` 表 + 状态机

健康问题转诊（体检/筛查/异常/手动来源）落独立表，状态机 `待转诊 → 已转诊 → 已完成`（+`已取消`），由应用层白名单管控；不强制关联 encounter（延续 052 口径）。

### De — 报告：后端只读聚合 + 前端打印，不引入 PDF 依赖

报告 = 后端 `GET /child-health-reports/:patient_id` 聚合 DTO（档案/体检与诊断/成长/接种/筛查/转诊/指导/过敏），前端 `ChildReportPage.tsx` 渲染可打印视图（浏览器打印→PDF），并提供 JSON/CSV 导出。**不在后端引入 PDF 库**（无既有依赖、跨栈风险大）。归档到 Nexus files（C3）为可选后续。

### Df — 用药安全：过敏与禁忌提醒为「分级提醒」，默认不硬拦

新增 `patient_allergies` 规范化表（回填 `patients.allergies` JSONB），检查引擎匹配药品（目录名/编码/交叉反应组）与过敏史，并按严重度产出提醒：**一般→提示可继续**，**严重/明确禁忌→强提醒并要求二次确认**。默认**非阻塞**（医生可签署继续），是否为严重项提供**硬拦截**见 §11 Q4。检查**不改变** `DrugCatalogPort` 的 fail-closed 目录校验。

### Dg — 持久化与迁移

新增/变更持久化一律**原生参数化 SQL**（`$1..$n` + `Tuple.of`，JSONB 绑 `JsonObject`/`JsonArray`，跨 schema 显式限定），不新增 jOOQ 引用、不重跑 codegen（`service-vertx-kotlin/AGENTS.md`）。迁移 `V531–V535` 各任务独占，互不冲突。

### Dh — 最小范围与隐私

儿童健康数据 + 监护人信息属敏感 PHI：报告 DTO 不返回身份证号；导出为本地文件、不落服务端（除非启用 C3）；过敏/诊断写操作受 `clinical:write`；不改医疗/养老域行为。

## 4. 分任务设计

- 输入：`scale_code`、儿童月龄、条目作答（`item_code → 分值`）。
- 输出：适龄条目集、领域分、总分、判读（正常/可疑/异常）、触发项。
- 校验：月龄超出量表适用区间 → 明确错误；缺项/非法分值 → 明确错误。
- 独立测试：`./gradlew :libs:healthcare:test --offline --tests '*DevelopmentalScoringTest'`（无 DB）。
