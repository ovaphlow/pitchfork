## 1. 背景与目标

052/053 已把儿保的**临床侧**（护士测量/成长/接种/异常/指导、医生筛查/诊断/转诊）闭环。但**非医生护士的六类岗位**（营养、康复、保育、药学、收费、系统管理）在儿保模式下仍缺日常能力；其中部分诉求**已有可复用能力**，必须先指认、再补齐，避免重复建设。

### Db — 康复师：复用 nursing 周期与计划；执行事实源唯一（rev2：BL7 + N15 + R3）

**复用**：`nursing_service_periods`（承载儿童康复周期，`encounter_id` 保持 NULL）、`nursing_plans` / `nursing_plan_items`（训练计划周期与措施明细）、`nursing_care_plan_revisions`（计划修订）、`TaskExecutionRoutes` 的注入式选码门禁（`rehab:execute`）。

**不修改**：`nursing_tasks` 表结构、`TaskExecutionService`（1800 行）、`nursing_plans` 列（**不给 `nursing_plans` 加 `patient_id`**，BL6/L8）。

**执行事实源唯一（BL7 → L7）**：`V410` 新建的 `nursing_child_rehab_sessions` 是「是否完成训练 / 完成度」的**唯一事实源**；儿童康复**不复用** `nursing_task_executions` 打卡链，`child-rehab-sessions` 不是投影、也不与打卡链并行。理由：B1 已决定不动 `nursing_tasks`，复用会让两条链在同一批表上再次交叉。

**`service_type` 取值（N15 → L10）**：新增值用**大写英文 code `CHILD_REHAB`**，与既有 CHECK 的英文枚举风格一致（`HOME_CARE/COMMUNITY_CARE/HOSPICE/ELDERLY_CARE`）；中文（如「儿保康复」）**仅用于前端展示标签**，不落库、不入 API code。

**V409 内容（含 R3 → L9 架构裁定）**：同一迁移内完成 ① `DROP`/`ADD` `nursing_service_periods_service_type_check`（**保留 `ELDERLY_CARE` 分支**，追加 `CHILD_REHAB`）；② 加部分唯一索引（**必须带 `service_type` 谓词**，不得影响既有四类周期）：

```sql
-- V409 内，与 service_type CHECK 重建同批
CREATE UNIQUE INDEX uq_nursing_service_periods_active_child_rehab
    ON nursing.nursing_service_periods (patient_id)
```

## 5. 接口契约（冻结，车道不得改）

统一前缀 `/crate-api/<module>/v1`；成功响应形状沿用仓库约定（单条对象 / 列表 `{records, meta:{total}}` / 错误 `{error}`）；`created_at/updated_at` 为 `OffsetDateTime`；扩展字段命名 `metadata`；ID 为 26 位 ULID。**下列路径为冻结契约**，`packages/shared/src/aceso.ts` 只增函数与类型，不改既有签名（追加点在 `:4662` 之后）。

> **N18 → L16 说明**：§5.4 对 `POST /dispenses` 的字段追加是**对 046 冻结路由的向后兼容增补**——既有字段与语义不变，新字段**可选**；既有消费方不传新字段必须仍返回 2xx（回归断言见 §8.4 第 4 条）。本计划**不修改**任何 046 已冻结路由的既有签名。
