## 2. 设计决策

### D1 — 创建表单加「部门（可选）」，两步写入不阻断创建

- 复用既有「一人一主部门」契约：`createIdentitySubject`（IDP）+ `replaceSubjectDepartment`（Nexus），**不新增接口**。
- 写入顺序：先建账号，再写角色，最后写部门；任一步失败**不回滚用户**，把失败项合并进创建后的行内提示，用户可在列表行内重试（沿用现有 `roleWarning` 模式）。
- 行内「设置部门」保留：用于后续调整归属。

### D2 — 409 中文化落在 `packages/shared/src/problem-message.ts`

- Nexus 的错误体保持英文（全服务一致）；只有**用户可见**的这两条删除冲突做中文映射，与既有 403/503 映射同一处、同一风格。
- 文案：
  - 部门：`该部门下还有 {N} 名成员，请先调整归属后再删除。`
  - 角色：`该角色已分配给 {N} 个用户，请先取消分配后再删除。`
- 匹配规则：`status === 409` 且 `problem.detail` 命中后端既有句式正则；**匹配不上不得吞错**，继续走既有兜底（`error`/`detail`/`title`/正文）。
- 纯函数 + 单测逐字锁定（同 `api-error-messages.test.ts` 现有口径）。

### D3 — 医疗域补齐两页，并让这两页文案走域词表

- `Sidebar.tsx` 的「医生诊疗」「医嘱核对」`domains` 由 `["养老"]` 改为 `["医疗","养老"]`。
- 副作用必须一起处理：这两页变为医疗/养老双域可见，`domain-labels.test.ts` 的「非养老域可见页面不得硬编码『长者』」约束随之生效。现状硬编码点：
  - `OrdersPage.tsx:940`「入住长者」、`972`「暂无入住长者」；
  - `OrdersCheckPage.tsx:66` 列头「长者」、`122` 占位符「…/长者/…」。
- 取词一律走 `lib/domain.ts`：渲染路径用 `useDomain()` + `DOMAIN_ENTITY`（医疗=居民、养老=长者、儿保=儿童），依赖数组必须稳定的回调/兜底文案用 `currentEntityLabels()`——与 `NursingPage.tsx:87/397/580` 的既有写法同源。
- 两个文件加入 `NON_ELDERLY_VISIBLE_COMPONENTS`，锁死回归。

### D4 — 部门列表：客户端搜索 + 排序，保持层级树语义

- 搜索：按**名称或编码**做大小写不敏感子串匹配；命中节点**及其祖先链**保留（否则「上级部门」列会指向看不见的行）。无命中给空态提示。
- 排序：`默认（层级）/名称/编码/成员数` + 升/降序；**在同一父节点下对兄弟子树排序**，层级与缩进不变。默认档位与现状逐字一致（`departments.sort_order, code`）。
- 计数：卡片标题显示 `匹配 N / 共 M 个`（无过滤时退化为 `共 M 个`）。
- 不做分页：仍 `page_size=100`；分页会把层级树拆到不同页，需另行设计。

## 3. 验收口径

1. **创建即带部门**：创建用户时可选部门；账号与部门都成功 → 列表「部门」列立即显示；部门写入失败 → 用户已创建提示可见、可在该行用「设置部门」补上；不选 = 不设置。
2. **409 中文**：删除仍有成员的部门 → `该部门下还有 1 名成员，请先调整归属后再删除。`；删除仍被分配的 Nexus 角色 → `该角色已分配给 1 个用户，请先取消分配后再删除。`；其它 409（如重复编码）文案不变。
3. **医疗域菜单**：医疗模式下侧边栏出现「医生诊疗」「医嘱核对」；两页在医疗模式不出现「长者」（出现「居民」）、在养老模式仍为「长者」。
4. **部门列表**：可按名称/编码过滤并保留祖先链；可按名称/编码/成员数升降序排列且层级不乱；空结果有提示；`编辑/删除/添加` 行为与改前一致。
5. **回归**：`pnpm test:unit:aceso` 全绿；`pnpm --filter @pitchfork/aceso build`（含 `astro check`）0 error；未触碰后端/迁移。

### 2026-10-02 — 车道基础设施事实（供后续轮次参考）

- `pi-subagents@0.74.0` 的后台（async）子代理要求宿主包提供 `@earendil-works/pi-agent-core/node`；当前全局安装为 `@earendil-works/pi-agent-core@1.0.0`，其 `exports` 只有 `.` 与 `./package.json`（0.84.2–0.99.2 均含 `./node`）→ 异步子代理启动即失败（`async-execution.js` 的 `spawnRunner` 宿主 peer 校验）。
- 工作绕过：工作流子项显式 `async: false` 走前台路径（`subagent-executor.js:3947/7330`），不经过 `spawnRunner`，本轮 worker 与 reviewer 均据此完成。仅工作流级 `async: false` 不生效——子项默认值取自 `asyncByDefault`。
- 根因是宿主包与扩展的版本错配，属环境问题；修复需用户决定（升级/对齐全局包），不在本计划范围。
