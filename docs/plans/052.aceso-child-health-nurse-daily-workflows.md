## 1. 背景与目标

产品已进入「儿保 / 儿童福利院」模式：035 把**儿童健康档案**（`person_type=儿童` + `child_health_profiles`）与档案表单落地，域词表（`lib/domain.ts`）也统一为「儿童」。但**护士（`nurse01`）的日常功能链**仍缺四块，且已落地的档案缺一张统一的护士工作台把它们串起来：

| 用户诉求 | 现状 | 缺口定性 |
|---|---|---|
| ① 儿童健康档案建立与体检记录 | 档案已交付（035）；儿保域可见「体检管理」 | 缺**按儿童、按月龄的儿保体检记录**（现有体检是机构年度批次） |
| ② 日常体温/身高体重测量与成长曲线追踪 | 体温可录（`vital_sign_records`）；有单指标趋势图 | **无身高/头围录入**（体征枚举无 `HEIGHT`），**无成长曲线**与百分位评价 |
| ③ 疫苗接种状态监控与提醒 | 035 仅存 `vaccination_records` JSONB 摘要 | 无**接种排程、状态判定、逾期提醒** |
| ④ 异常情况识别与家长通报 | 成人阈值异常 + 养老域「异常告警」页 | 儿童阈值不匹配；**无家长通报** |
| ⑤ 日常健康指导 | 无 | 无**指导模板与开展记录** |

**目标**：在儿保域建立一条「建档 → 日常测量 → 成长/接种/体检评估 → 异常识别 → 家长通报 → 健康指导」的护士日常闭环，全部写入受既有权限码（`health:manage` / `clinical:write`）管辖，读写契约、模块边界与迁移号段符合仓库既有约束。

### 1.1 分阶段总览（每阶段可独立派工、独立验收）

| 阶段 | 主题 | 迁移 | 主要交付 | 依赖 |
|---|---|---|---|---|
| P1 | 儿保体检记录 | `V526` | `child_health_checkups` + 服务/路由 + 儿保体检页 | 035 |
| P2 | 成长测量与成长曲线 | `V527` | `child_growth_measurements` + 曲线引擎 + 成长页 | P1（可并行） |
| P3 | 预防接种监控与提醒 | `V528` | `child_vaccination_records` + 排程常量 + 接种页 | 035、P4 消息 |

## 3. 总体设计决策

### D1 — 儿保体检单独建表，不动年度批次

新增 `child_health_checkups`（按儿童、按月龄的保健体检记录）。**不复用** `health_checkups`：后者以 `checkup_year` 唯一约束表达「机构年度批次」，与儿童 0–3 岁高频保健体检（满月/3/6/9/12/18/24/36 月）语义冲突。年度体检管理保持现状，可继续把儿童纳为 `health_checkup_members`。

### D2 — 身高/体重/头围单独建表，体温沿用体征

新增 `child_growth_measurements`（一次测量会话一行，`height_cm`/`weight_kg`/`head_circumference_cm` 可空）。**不扩** `vital_sign_records`：其 `type` CHECK 无 `HEIGHT`/`HEAD_CIRCUMFERENCE`，且异常按成人固定阈值、`WEIGHT` 恒不判异常，与儿保「按 WHO 百分位评价」口径不同。**体温仍写 `vital_sign_records`**（已工作）；儿保测量页一次录入同时写体温（体征表）与身高体重新表，避免护士分两处录。

### D3 — 成长曲线：前端纯函数 + 内置参考数据

后端只返回**原始测量序列**与落库时的**评价快照**（percentile / z-score，允许为空）；百分位计算与曲线绘制为前端纯函数 `lib/growth.ts`，参考数据（WHO Child Growth Standards LMS，0–5 岁）作为可版本化常量文件。口径与既有「阈值常量化」（V509/`CheckupService`）一致，避免 DB 内容管理。参考标准与年龄范围见 §14 待裁定。

### D4 — 预防接种：规范化记录 + 读时状态 + 显式提醒

新增 `child_vaccination_records` 规范化表，**一次性回填** `child_health_profiles.vaccination_records` JSONB；排程为静态常量 `VACCINATION_SCHEDULE`（国家免疫规划疫苗 × 推荐月龄）；状态（已接种/待接种/临期/逾期/暂缓/拒种）**读时计算**；提醒 = 读时清单 + 护士**显式**「生成提醒」动作。**不做后台定时任务**：仓库无调度器，且 042 已确立「操作人与时点由服务端派生」范式。

### D5 — 儿童异常识别分流，不套成人阈值

儿童异常统一在儿保读端点聚合：体温（沿用发热阈值）、心率/呼吸（按年龄段分档，见 §14）、生长（百分位 P3/P97）、接种逾期、体检异常。成人 `vital_sign_records.abnormal` 计算**不修改全局常量**，仅对 `person_type=儿童` 按年龄档解析阈值（新增 `ChildVitalThresholds` 常量 + 解析函数）。

### D6 — 家长通报消费 Nexus messages，不重建消息栈

根 `AGENTS.md`：`messages` 是 Nexus 能力，只消费 `/crate-api/shared/v1/*`。儿保后端在「通报」动作中调用 Nexus `POST /messages`（`message_type=child_health_alert`，`receiver_type=guardian`，`payload` 含儿童、异常、内容快照），并在本域写一条**通报台账** `child_health_notifications`（引用 `message_id`、渠道、对象、内容快照）以便按儿童查询。**真实外发渠道（短信/微信）若无接入，渠道标记「站内/待接入」，不得宣称已送达**——渠道现状见 §14。

### D7 — 健康指导：模板常量 + 开展记录

指导模板 `GUIDANCE_TEMPLATES`（月龄段 × 主题：喂养/睡眠/口腔/安全/发育促进/疾病预防）为静态常量；`child_health_guidance_records` 记录每次指导（模板码、内容快照、时间、操作人、渠道），可一键转家长通报（复用 D6）。

### D8 — 权限复用既有码，不新增

儿保所有写操作沿用 `health:manage`；异常**确认/转诊**沿用 `clinical:write`（048 D1）。新增路由必须登记进 `DECLARED_PERMISSIONS`（集中式），否则视为未完成。是否新增儿保专属码见 §14。

### D9 — 迁移与原生 SQL 执行通道

迁移号段 `V526`–`V530`，各阶段一条，互不冲突；新增/变更的持久化一律**原生参数化 SQL**（`$1..$n` 占位 + `Tuple.of(...)` 按序绑定，JSONB 绑 `JsonObject`/`JsonArray`，跨 schema 显式限定），**不新增 jOOQ 引用、不重跑 jOOQ codegen**，遵循 `service-vertx-kotlin/AGENTS.md` 的持久化规则。

### D10 — 最小范围与隐私

儿童属未成年人，档案含监护人电话与健康数据。新读路由受默认拒绝总闸（需登录）；新写路由受 `health:manage`；通报 payload 只带必要字段、不落身份证号；不新增导出；不改医疗/养老域行为。

## 4. 分阶段设计

### P1 — 儿保体检记录（V526）

**数据模型** `child_health_checkups`：

| 列 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(32) PK | ULID |
| patient_id | VARCHAR(32) NOT NULL REFERENCES patients(id) | 儿童 |
| checkup_date | DATE NOT NULL | 体检日期 |
| checkup_type | VARCHAR NOT NULL | 「满月/3月/6月/9月/12月/18月/24月/3岁/常规」应用层白名单 |
| age_months | INTEGER | 体检时月龄（服务端按 `birth_date` 派生落库，便于固定口径） |
| items | JSONB DEFAULT '[]' | 检查项与结果（项目/结果/结论，结构随 UI 演化） |
| conclusion | VARCHAR | 正常 / 异常 / 需转诊（应用层白名单） |
| guidance | TEXT | 本次指导 |
| next_checkup_date | DATE | 建议下次体检日期 |
| operator | VARCHAR NOT NULL | 操作人（认证主体，客户端不得提交） |
| remark / metadata / created_at / updated_at | | |

**接口**（`/crate-api/healthcare/v1`，写接 `health:manage`）：

- `POST /child-health-checkups`：创建（校验 `person_type=儿童`；`age_months` 服务端派生）。
- `GET /child-health-checkups?patient_id=&from=&to=`：按儿童查询。
- `GET /child-health-checkups/:id`；`PATCH /child-health-checkups/:id`（修正）。

**前端**：儿保域新增「儿童体检」页（或在儿童档案详情内以 Tab 承载）；列表按儿童分组、显示月龄与结论；表单含 D2 检查项与下次体检日期，异常结论可「转异常/转随访」。

### P2 — 成长测量与成长曲线（V527）

**数据模型** `child_growth_measurements`：

| 列 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(32) PK | ULID |
| patient_id | VARCHAR(32) NOT NULL REFERENCES patients(id) | 儿童 |
| measured_at | TIMESTAMPTZ NOT NULL DEFAULT now() | 测量时间 |
| age_days | INTEGER | 测量时天龄（服务端按 `birth_date` 派生落库） |
| height_cm / weight_kg / head_circumference_cm | NUMERIC | 可空，一次会话至少一项 |
| percentile_snapshot | JSONB | 落库时评价快照 `{height:{p,z},weight:{...}}`，可空 |
| operator | VARCHAR NOT NULL | 操作人（认证主体） |
| note / metadata / created_at / updated_at | | |

**接口**（写接 `health:manage`）：

- `POST /child-growth-measurements`（体温字段同时写 `vital_sign_records`，由服务端在同一请求内落两表）。
- `GET /child-growth-measurements?patient_id=&metric=&from=&to=`。
- `GET /child-growth-series/:patient_id`：按指标聚合的绘图序列（含年龄轴）。
- `DELETE /child-growth-measurements/:id`（软删）或 `PATCH` 修正。

**前端**：新增 `lib/growth.ts`（LMS → z-score/百分位，纯函数）+ `components/ChildGrowthPage.tsx`（测量录入 + P3/P15/P50/P85/P97 曲线 + 单点落图 + 评价文本）。

### P3 — 预防接种监控与提醒（V528）

**数据模型** `child_vaccination_records`：`id / patient_id / vaccine_code / vaccine_name / dose_no / administered_at / facility / batch_no / status(已接种/暂缓/拒种) / operator / note / metadata / created_at / updated_at`；一次性从 035 的 `vaccination_records` JSONB 回填。

**排程常量** `VACCINATION_SCHEDULE`（国家免疫规划疫苗 × 推荐月龄，含剂次与窗口）；**状态判定** `vaccinationStatus(records, schedule, birthDate, now)`：已接种 / 待接种 / 临期 / 逾期。

**接口**（写接 `health:manage`）：

- `POST /child-vaccinations`；`GET /child-vaccination-records?patient_id=`。
- `GET /child-vaccination-status/:patient_id`：逐条排程状态 + 逾期汇总。
- `POST /child-vaccination-status/:patient_id/remind`：对逾期/临期项生成家长提醒（调用 D6 通报）。

**前端**：`components/ChildVaccinationPage.tsx`——排程表（疫苗 × 月龄 × 状态徽标）、录入接种、逾期高亮与「生成提醒」。

### P4 — 异常识别与家长通报（V529）

**数据模型** `child_health_notifications`：`id / patient_id / alert_type / alert_ref / guardian_name / guardian_phone / channel / content / message_id / status / operator / created_at`。阈值解析常量 `ChildVitalThresholds`（年龄段 × 体温/心率/呼吸）。

**接口**：

- `GET /child-health-alerts?patient_id=&status=`：聚合读（体温异常 / 生长异常 / 接种逾期 / 体检异常），`health:manage` 只影响写、读保持开放（046 D7）。
- `POST /child-health-notifications`（`health:manage`）：登记通报并调用 Nexus `POST /crate-api/shared/v1/messages`。
- `GET /child-health-notifications?patient_id=`。

**前端**：儿保域新增「异常提醒/家长通报」页（可扩展 `AbnormalAlertsPage` 支持儿保域，或新增 `ChildHealthAlertsPage.tsx`）；异常卡片带「通报家长」动作与通报台账。

### P5 — 日常健康指导（V530）

**数据模型** `child_health_guidance_records`：`id / patient_id / template_code / age_band / topic / content / delivered_at / channel / operator / metadata / created_at`；模板 `GUIDANCE_TEMPLATES` 为静态常量。

**接口**（写接 `health:manage`）：`GET /child-guidance-templates?age_months=`、`POST /child-guidance-records`、`GET /child-guidance-records?patient_id=`。

## 5. 接口契约（冻结，车道不得改）

统一前缀 `/crate-api/healthcare/v1`；成功响应形状沿用仓库约定（单条对象 / 列表 `{records, meta:{total}}` / 错误 `{error}`）；时间字段 `created_at/updated_at` 为 `OffsetDateTime`；扩展 JSON 字段命名 `metadata`。上述 `POST/GET/PATCH/DELETE` 路径为**冻结契约**，`packages/shared/src/aceso.ts` 只增对应函数与类型，不改既有函数签名。

写入路由登记（`DeclaredPermissions.kt` `DECLARED_PERMISSIONS` 新增 `CENTRAL` 项，码 `health:manage`；异常确认/转诊 `clinical:write`）；读路由（`GET`）不上门禁。

## 9. 验收口径

1. **儿保体检**：儿童可建/查/改体检记录；`age_months` 服务端派生与 `formatAge` 口径一致；异常结论可转异常。
2. **成长曲线**：可录入身高/体重/头围（一次会话一行）；曲线含 P3/P15/P50/P85/P97 参考带与实测点；`growth.ts` 边界单测（出生当天、跨月、参考点 z≈0、P50 中位）全绿；体温录入仍落 `vital_sign_records`。
3. **预防接种**：035 JSONB 记录回填后逐条可查；`vaccinationStatus` 对「未到龄/已接种/临期/逾期」判定正确（单测锁定）；「生成提醒」产生 Nexus message 且台账可查。
4. **异常与通报**：儿童体征异常按年龄档判定（温度/心率/呼吸），成人阈值不变；生长异常按 P3/P97；通报登记可查且引用 `message_id`；渠道未接入时明确标注，不谎报送达。
5. **健康指导**：按当前月龄推荐模板、可保存开展记录、可转通报。
6. **权限与回归**：所有新增写路由在 `DECLARED_PERMISSIONS` 有 `CENTRAL` 声明且被 `SubjectPermissionGateTest`/`DeclaredPermissionsTest` 覆盖；无码账号 403（中文），有码 2xx；医疗/养老域回归不变；`domain-labels.test.ts`/`age.test.ts` 全绿；`./gradlew :libs:healthcare:test` 全绿；`pnpm --filter @pitchfork/aceso build` 0 error；`pnpm test:unit:aceso` 全绿。
7. **真库**：`ChildHealthWorkflowIntegrationTest` 覆盖各阶段创建/查询/校验/通报，fixture 残差为 0。

## 12. 裁定结果（2026-10-06 按推荐口径确认，冻结）

八项已裁定，均采纳推荐口径；实施阶段不得偏离，如需变更须回到本计划重新裁定：

| # | 事项 | 裁定 | 影响 |
|---|---|---|---|
| 1 | 成长参考标准 | **WHO Child Growth Standards，0–5 岁** | P2 `growth.ts` 内置 WHO LMS 常量；不含中国九市标准 |
| 2 | 年龄覆盖 | **0–5 岁 MVP** | 超出 5 岁不画曲线，仅存原始测量；0–18 岁列入后续 |
| 3 | 预防接种范围 | **仅国家免疫规划疫苗** | P3 `VACCINATION_SCHEDULE` 只含免疫规划疫苗；非免疫规划后续 |
| 4 | 家长通报渠道 | **站内台账 + Nexus message + 渠道字段预留，无真实外发** | P4 不接入短信/微信；渠道未接入时记录为「站内/待接入」，不得宣称已送达 |
| 5 | 儿保体检模型 | **新增 `child_health_checkups`** | P1 不改造年度 `health_checkups`；年度体检管理保持现状 |
| 6 | 权限 | **复用 `health:manage`（异常确认/转诊 `clinical:write`）** | 不新增 `child:manage`；所有新增写路由登记进 `DECLARED_PERMISSIONS` |
| 7 | 体温录入归属 | **儿保测量页合并录入，落回 `vital_sign_records`** | P2 一次提交写两表；不单开体温页 |
| 8 | 实施顺序 | **P1→P2→P3→P4→P5** | 各阶段独立派工、独立验收；迁移 V526–V530 顺序占用 |
