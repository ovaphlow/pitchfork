# 056 — Aceso 收窄为养老单产品：移除医疗/儿保域，路由改为 `/eldercare/*`

- 创建时间：2026-11-21
- 状态：**计划中（待用户批准后进入开发）**
- 上游：035（儿保儿童健康）、052–054（儿保护理/医生/角色工作流）、047/048/049/050（域与门禁）
- 范围：`ui-astro/apps/aceso`、`ui-astro/packages/shared`、`service-vertx-kotlin/libs/{healthcare,nursing,dining,pharmacy}`、`apps/aceso`、`docs/architecture.md`
- **无服务启停**（遵循根 AGENTS.md 2026-09-29 生命周期政策）；开发库 `5432` 不清理、不重置

---

## 1. 背景与目标

Aceso 目前用运行期偏好 `localStorage["aceso-domain"]` 在**医疗 / 养老 / 儿保**三个域之间切换，
三个域共用同一套 `/dashboard/*` 路由与同一套菜单树，仅靠 `domains: Domain[]` 过滤菜单项、
靠 `domainLabels` 改写文案。结果是：

1. 功能按域混在一起，路径不表达产品语义（`/dashboard/elders` 在儿保域叫「儿童档案」）；
2. 儿保（035/052/053/054）已把 12 个 healthcare 服务、8 个 nursing 服务以及 dining/pharmacy
   的儿童特化铺进 4 个 lib，共 1 万余行，与养老服务共用同一进程与同一批表；
3. 部分通用功能（药师/收银工作台、基础数据维护、操作审计）被误声明为**仅儿保可见**。

用户决定（2026-11-21）：

- Aceso **只保留养老**，医疗与儿保从当前形态中移除；
- 「去掉医疗」= 只删除**域模式**，临床能力（住院、医嘱、药房、体检、慢病、收费）继续为养老服务；
- 儿保**代码与迁移全量删除**，**表保留**在既有库中（未来以另一种形式重做，例如二级路由 `/childcare/*`）；
- 路由改为一级产品域前缀 `/eldercare/*`，`/dashboard/*` 直接废弃，不做兼容跳转页；
- 系统设置类页面（用户/角色/部门/仓库/物资/床位/费用项目/基础数据/审计日志）统一放 `/eldercare/*` 下；
- 目前仅儿保可见的通用功能归入养老并保留。

非目标：本次不动 Trainova、platformd、agora、service-prototype；不重做儿保；不改动 DB 中已有的
`child_*` 表数据（保留待未来迁移或清理）。

### 2.3 迁移可删性的已核实依据

`libs/database/src/main/kotlin/com/ovaphlow/crate/database/DatabaseConfig.kt` 的 Flyway 配置含
`.ignoreMigrationPatterns("*:missing", "*:ignored")`，因此**删除已应用的迁移文件不会阻塞启动**，
`flyway_schema_history` 中的旧记录被忽略，既有库中的 `child_*` 表保持原样（本次口径：保留）。

## 5. 关键决策

| # | 决策 | 选择 | 理由 |
| --- | --- | --- | --- |
| D1 | 「去掉医疗」的含义 | 只删域模式，保留临床能力 | 用户 2026-11-21 确认；养老本身依赖住院/医嘱/药房/收费 |
| D2 | 儿保代码与迁移 | 全量删除代码与迁移文件，表保留 | 用户确认；Flyway 忽略 missing，删除不阻塞启动；未来重做儿保时重新设计表结构 |
| D3 | `patients.person_type` | 列与历史值保留，后端继续接受 `居民/长者/儿童` 三值，前端只写「长者」 | 既有库可能已有 `儿童` 行；删值校验会造成历史档案不可读；待儿保重做时再定口径 |
| D4 | 路由前缀 | `/eldercare/*` 一级 | 用户确认；未来 `/childcare/*` 平行，物理隔离 |
| D5 | 系统设置页归属 | 全放 `/eldercare/*` | 用户确认；当前只有养老一个产品 |
| D6 | 旧 `/dashboard/*` | 直接废弃，不生成跳转页 | 用户确认；减少静态页面与长期债 |
| D7 | 仅儿保可见的通用功能 | 归入养老保留（药师/收银/营养师工作台、基础数据维护、操作审计） | 用户确认；它们与儿保业务无关，是菜单声明错误 |
| D8 | 儿保权限码 | 不新增、不删除权限码常量；只删路由声明 | 权限码已被角色数据引用，删码会破坏 `platformd` 角色配置 |
| D9 | 发布节奏 | 单次交付，不分批上线 | 前端路径与后端路由无跨产品依赖，分两批会留下中间态 |
