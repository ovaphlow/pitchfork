# Nexus Shared 角色目录与权限码集合实施计划

更新时间：2026-08-20

状态：开发候选版本

## 1. 背景、前置与目标

Aceso 养老/福利院路线已完成用户、部门、仓库等基础管理，`/dashboard/roles` 角色管理页仍是占位
（"待后续计划"）。身份系统（`service-idp-go`）已有 `identity_roles`/`identity_subject_roles` 表，
seed 了 `identity.admin`、`identity.audit.read`，subject 序列化返回 `roles: string[]`，但没有角色目录
的 CRUD API，也不存在"角色 → 权限码集合"的共享定义。

用户确认：在 `service-nexus-shared/` 实现**角色目录 CRUD + 每个角色的权限码集合**，作为共享字典
能力供各产品消费；并把 Aceso 的 `roles.astro` 占位页接成真实角色管理页（后端 + 前端一起交付）。
subject↔角色 的分配仍留在 IDP 既有表，不在本期引入。

Nexus Shared 是 Rust/Axum/SQLite（WAL）的共享能力层，现有 Settings（部门/仓库）、Messages、Files、
Interactions 四模块，通过 `crate-api/shared/v1/*` 对外，经 IDP HTTP 会话端点认证。角色目录复用
Settings 的字典管理模式（category+code+payload），但角色是独立事实（唯一 role_code + 权限码集合），
不复用 settings 表伪造。

### 1.1 必须实现

1. Nexus 新增 `roles` 模块：`GET/POST /roles`、`GET/PUT/DELETE /roles/{id}`，受既有
   `require_identity` 认证保护；
2. 角色目录表：`role_code` 唯一、`display_name` 必填、`description` 可选、权限码集合
   `permission_codes`（JSON 字符串数组）可空；
3. 创建/更新校验：`role_code` 非空且格式受控（小写字母/数字/点），`display_name` 非空，
   `permission_codes` 若提供必须为字符串数组且元素去重；
4. `role_code` 唯一冲突返回 `409`，不存在返回 `404`，请求体非法返回 `400`；列表按
   `role_code` 排序并支持 `page`/`page_size` 分页；
5. 列表/详情/创建/更新/删除均要求已认证会话（无会话 401），与 Settings 等模块一致；
6. 提供 `@pitchfork/shared/aceso` 类型化客户端函数（listRoles/createRole/updateRole/deleteRole），
   经 `service: "nexus"` 请求，复用 token/JSON/401 清理；
7. Aceso `roles.astro` 由占位改为真实角色管理页（组件 `RolesPage.tsx` 放入
   `apps/aceso/src/components/`）：角色列表、创建、编辑、删除、权限码编辑与错误展示；
8. 提供不访问数据库的单元测试（校验函数）、Nexus 模块测试（内存 SQLite + 认证桩）、
   Shared 客户端类型构建验证，以及默认编译/构建验证。

### 1.2 明确不在本期范围

- 不实现"用户 ↔ 角色 分配"API（保留在 IDP `identity_subject_roles`）；
- 不实现权限点（permission）独立表/枚举定义；本期权限码仅是角色上的字符串集合；
- 不做基于角色的鉴权中间件（如 `require_role("admin")`）；本期只做角色目录的增删改查；
- 不改写 IDP 的 `identity_roles` 表或 seed 逻辑；Nexus 角色目录与 IDP 角色在语义上可并存，
  关联/同步策略不在本期；
- 不做角色删除的级联或引用检查（本期为字典管理，删除直接移除目录项）；
- 不在本期接入 Aceso 用户页的角色分配编辑（UsersPage 仍只读展示 IDP 角色 badge）。

## 3. 领域规则与数据设计

### 3.1 角色目录表

在 `service-nexus-shared/migrations/` 新增迁移（例如 `0002_roles.sql`），SQLite：

```sql
CREATE TABLE IF NOT EXISTS roles (
    id                TEXT PRIMARY KEY,                -- ULID
    role_code         TEXT NOT NULL UNIQUE,            -- 角色编码，唯一
    display_name      TEXT NOT NULL,                   -- 显示名称，必填
    description       TEXT NOT NULL DEFAULT '',        -- 描述，可选
    permission_codes  TEXT NOT NULL DEFAULT '[]',      -- JSON 字符串数组
    created_at        TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now')),
    updated_at        TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%fZ', 'now'))
);

CREATE INDEX IF NOT EXISTS idx_roles_role_code ON roles(role_code);
```

### 3.2 规则

- `role_code`：小写字母/数字/点组成（如 `nursing.staff`、`pharmacy.manager`），长度受限
  （建议 1..64）；创建后不可变；
- `display_name`：非空，去除首尾空白后必须非空；可重复？——不要求唯一（角色编码唯一即可）；
- `permission_codes`：可空；若提供必须为 JSON 字符串数组，服务端去重并保持稳定顺序写入；
- 删除：直接删除目录项，返回 `204`；不存在返回 `404`；
- 更新：`PUT /roles/{id}` 完整替换 `display_name`/`description`/`permission_codes`；
  `role_code` 创建后不可改，改码返回 `400`；
- 分页：复用 `PageQuery.limit_offset()`（page≥1、page_size 1..100），列表按 `role_code` 升序；
- 列表返回 `[{...}]` 数组（与 Settings 一致），不做 `records/meta` 包装（Nexus 约定）。

## 4. 实现设计

### 4.1 Nexus roles 模块

- 新增 `src/roles/mod.rs`，导出 `pub fn router() -> Router<AppState>`，路由：
  - `GET /` → list（支持 `page`/`page_size`）
  - `POST /` → create（201）
  - `GET /{id}` → get_one（200 / 404）
  - `PUT /{id}` → replace（200 / 404；role_code 不可改返回 400；409 为防御性映射，实际业务中不可达）
  - `DELETE /{id}` → delete（204 / 404）
- 复用 `ApiError`/`ApiResult`/`PageQuery`/`AppState.database`/`ulid::Ulid`；
- `permission_codes` 存储为 JSON 字符串，序列化/反序列化用 `serde_json`；
- 唯一冲突映射：`map_write_error` 判断 SQLite `2067`/`1555` → `ApiError::Conflict`；
- 认证由 `lib.rs` 的 `require_identity` 中间件统一覆盖（新模块挂到 protected router）。

### 4.2 lib.rs 挂载

在 `app()` 的 protected router 增加 `.nest("/roles", roles::router())`，并 `pub mod roles;`。

### 4.3 Shared 客户端（aceso.ts）

```ts
export interface NexusRole {
  id: string;
  role_code: string;
  display_name: string;
  description: string;

  role_code: string;

```

### 4.4 Aceso 角色管理页

- `roles.astro` 改为挂载 `RolesPage`（放在 `apps/aceso/src/components/`）；
- `RolesPage.tsx`：角色列表表格、创建/编辑弹窗（role_code、display_name、description、
  权限码逗号分隔输入→数组）、删除确认；提交期间禁用按钮、失败保留表单、成功刷新列表；
  错误经 `errorMessage()` 展示，不显示 SQL/堆栈；
- 只经 `@pitchfork/shared/aceso` 请求，不直接 `fetch`。

## 5. API 契约

路径前缀 `/crate-api/shared/v1/roles`。列表返回 JSON 数组；单条返回对象；错误 RFC9457 Problem
Details（与既有 Nexus 模块一致）。

```text
GET    /roles?page=1&page_size=20       → 200 [{...}]
POST   /roles                           → 201 {...} | 400 | 409
GET    /roles/{id}                      → 200 {...} | 404
PUT    /roles/{id}                      → 200 {...} | 400 | 404   （role_code 不可改，返回 400）
DELETE /roles/{id}                      → 204 | 404
```

无有效会话：`401`（Problem Details `not-authenticated`）。请求体示例：

```json
{
  "role_code": "nursing.staff",
  "display_name": "护理人员",
  "description": "护理站日常护理与执行",
  "permission_codes": ["nursing:execute", "nursing:record"]
}
```

## 7. 风险与控制

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 权限码是自由字符串 | 无枚举约束 | 本期仅字典管理，明确不在范围；未来另立权限点计划 |
| 与 IDP 角色表并存歧义 | 用户困惑 | 文档明确 Nexus=目录、IDP=分配；不在本期同步 |
| 删除角色无引用检查 | 目录与引用脱节 | 本期定位字典管理，记录残余风险 |
| 认证未覆盖新模块 | 未授权访问 | 挂到 protected router，测试断言 401 |
| PUT 409 实为死分支 | 契约与实现不一致，误导调用方 | `role_code` 不可改，改码返回 400；`map_write_error` 的 409 分支保留为防御性映射，§5 契约已标注不可达 |
| 列表仅取第一页 20 条 | 角色 >20 时 UI 不可见，无分页控件 | `listRoles()` 默认 page_size=20（`lib.rs:42`），UI 无分页控件；需后续计划接入分页控件 |
| description 显式 null | 400 错误，与"可选"口径不一致 | 已修复：`RoleInput.description` 改为 `Option<String>`（2026-08-20） |
