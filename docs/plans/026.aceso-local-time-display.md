# Aceso 全站时间显示与录入时区统一实施计划（026）

更新时间：2026-09-29
状态：实施中
分支：`fix/aceso-local-time-display`（worktree `.worktrees/aceso-local-time`）

## 1. 背景与根因

用户实测报告（2026-09-29）：

- 本地 15:17 录入体温 39.5，接口正确存 `measured_at: "2026-09-28T07:17Z"`；
- 页面却显示 `2026-09-28 07:17`——护士刚录完就看到早了 8 小时；
- 同一页面的输入框默认值用的是**本地时间**（`todayLocal()`），
  查询筛选又**硬编码 `+08:00`**；
- 医嘱开始时间 07:00、护士核对 14:28、病程记录 02:00 都是同样的 UTC 原文。

对一个吃药、测体征的系统，时间轴错 8 小时是不可接受的。

### 1.1 根因

前端没有时间层，每个组件各自为政，全站并存**四套互相冲突的口径**：

| # | 口径 | 典型写法 | 出现处 | 后果 |
|---|---|---|---|---|
| A | **UTC 原文截断** | `value.slice(0,16).replace("T"," ")` | 13 处（HealthMonitor/Orders/Nursing/Admissions/Dining/Pharmacy/AbnormalAlerts/Activities/Checkup/Followup/OrdersCheck/Requisitions/PurchaseOrders） | 展示早 8 小时（**用户主诉**） |
| B | **浏览器本地时区** | `new Date(v)` + `getHours()` / `toLocaleString` | Billing、Deposits、FeeItems、UsersPage | 换一台非东八区设备即错 |
| C | **UTC-naive 输入默认值** | `new Date().toISOString().slice(0,16)` | Nursing（4 处）、Activities、ChronicDisease、NursingExecutionStatisticsPanel | 护士 15:17 打开表单，默认填 `07:17`；提交时再按本地解释，等于把 15:17 记成前一天 23:17 |
| D | **硬编码 `+08:00` 拼接** | `` `${x}:00+08:00` `` | HealthMonitor、Orders、Admissions、Followup、AbnormalAlerts | 与 A 互相矛盾：录入按东八区、展示按 UTC |

后端口径是**唯一的、正确的一侧**，不动：

- Kotlin 侧 `businessZone = ZoneId.of("Asia/Shanghai")`（HealthcareService、VitalSignService、MedicalOrderService、CheckupService、ChronicDiseaseService、FollowupService 均如此）；
- 时间戳列是 `TIMESTAMPTZ`，响应为 UTC 瞬时（`...Z`）；
- 纯日期列是 `DATE`，响应为 `YYYY-MM-DD`；
- 筛选参数按 `OffsetDateTime.parse` 解析，**要求带偏移**。

### 1.2 结论

后端已经确定「业务时区 = Asia/Shanghai」。前端缺的不是「换成浏览器本地」，
而是**一个与后端 businessZone 同口径的共享时间层**，并让展示 / 录入 / 筛选三处都走它。

## 2. 目标与范围

### 2.1 必须实现

1. 新增 Aceso 应用内唯一时间模块 `ui-astro/apps/aceso/src/lib/datetime.ts`，
   时区**钉死 `Asia/Shanghai`**，与后端 `businessZone` 同口径，且**不依赖宿主/浏览器时区**
   （用 `Intl.DateTimeFormat` + `formatToParts`，禁止 `Date#getHours()` 与 `toLocaleString()` 解析）。
2. 全站**展示**时间戳统一按业务时区格式化：`2026-09-28T07:17Z` → `2026-09-28 15:17`。
3. 全站**录入**默认值统一按业务时区墙钟生成（`nowLocalInput()`），
   提交时统一经 `toOffsetDateTime()` 显式携带 `+08:00`，不得依赖浏览器时区。
4. 全站**编辑回填**统一经 `toInputValue()` 把瞬时转回业务时区 `datetime-local` 文本。
5. 全站**筛选边界**统一经 `dayBoundary()` 生成带偏移的开/闭边界，删除裸 `+08:00` 拼接。
6. 纯日期字段（`YYYY-MM-DD`）**不做任何时区换算**，原样透传；日期加减只做日历运算。
7. 删除 20 个组件中重复/冲突的本地 helper 定义，改为从 `lib/datetime.ts` 导入。
8. 为共享模块补齐单测，并在**三个不同宿主时区**下证明结果不受宿主时区影响。

### 2.2 明确不在本期范围

- 不修改任何后端 Kotlin 代码、迁移、SQL 或 API 契约；
- 不修改 `packages/shared`（API 客户端）、`packages/ui`（通用组件）；
- 不修改其他产品应用（admin / auth / merit / worker，实测它们没有本缺陷）；
- 不引入 `dayjs` / `date-fns` / `luxon` 等新依赖；
- 不为「用户可自选时区」做设置项；本产品是单一固定机构（中国），业务时区就是 `Asia/Shanghai`；
- 不改动任何业务逻辑、字段名、校验规则或接口调用顺序，只改时间的产生与呈现；
- 不新增 E2E 用例（E2E 需用户管理的真实服务，本期默认不执行）。

## 3. 时区契约（本期定稿）

| 层 | 规则 |
|---|---|
| 接口 | 瞬时（`TIMESTAMPTZ`）响应为 UTC 瞬时 `...Z`；纯日期响应为 `YYYY-MM-DD` |
| 展示 | 瞬时一律转业务时区 `Asia/Shanghai` 后格式化 |
| 录入 | `datetime-local` 文本一律**视为** `Asia/Shanghai` 墙钟；提交显式带 `+08:00` |
| 筛选 | 日期边界按 `Asia/Shanghai` 计算，显式带 `+08:00` |
| 纯日期 | 不做时区换算 |

固定 `+08:00` 的理由：中国无夏令时；后端同样固定 `Asia/Shanghai`；
护士站设备时区被误设时，展示仍等于机构墙钟，不产生「同一患者两个时间」。

## 4. 共享模块 API（冻结）

`ui-astro/apps/aceso/src/lib/datetime.ts`

```ts
export const BUSINESS_TIME_ZONE = "Asia/Shanghai";

formatDateTime(value: string | null | undefined, empty = "-"): string  // 瞬时 → "YYYY-MM-DD HH:mm"
formatDate(value: string | null | undefined, empty = "-"): string      // 纯日期透传；瞬时 → 业务时区日期
formatTime(value: string | null | undefined, empty = "-"): string      // 瞬时 → "HH:mm"；纯日期 → empty
todayLocal(): string                                                   // 业务时区今天 "YYYY-MM-DD"
nowLocalInput(): string                                                // 业务时区现在 "YYYY-MM-DDTHH:mm"
daysAgoLocal(days: number): string                                     // 业务时区今天 - days
toOffsetDateTime(localInput: string): string                           // "…T15:17" → "…T15:17:00+08:00"
toInputValue(value: string | null | undefined): string                 // 瞬时 → datetime-local 文本
dayBoundary(date: string, edge: "start" | "end"): string               // "YYYY-MM-DD" → 闭区间边界
addDays(date: string, days: number): string                            // 纯日期日历加减
weekStartOf(date: string): string                                      // 纯日期所在周周一
```

细则：

- 入参分类：空 → `empty`（`toInputValue` 为 `""`）；`YYYY-MM-DD` → 纯日期；
  `YYYY-MM-DDTHH:mm[:ss]` 无偏移 → **按 Asia/Shanghai 墙钟解释**；
  其余 → `new Date(value)`，`NaN` 时**原样返回入参**（不吞成 `-`）。
- `empty` 第二参数用于保留各页面既有占位符差异（`-` 与 `—` 都存在于现状，**不得改变可见输出**）。
- `formatTime` 对纯日期返回 `empty`；`formatDateTime` 对纯日期**只返回日期本身**（`"2026-07-01"`），
  **不得**合成 `"… 00:00"`——纯日期字段没有时刻，凭空补一个午夜等于伪造临床数据，
  且旧实现 `slice(0,16)` 对纯日期本就输出 `"YYYY-MM-DD"`。
  （2026-09-29 修订：初稿曾定为 `"YYYY-MM-DD 00:00"`；评审证明当前无 `DATE` 字段进入 `formatDateTime`，
  故零运行时影响，但仍按「不伪造数据 + 不改变既有可见输出」改为返回日期本身。）
- `dayBoundary` 只接受 `YYYY-MM-DD`；**传入完整时间时原样返回**，交由后端 `OffsetDateTime.parse` 报错，
  不得静默截断成当天 00:00（静默截断会把筛选条件悄悄放宽为整天）。
- `addDays` / `weekStartOf` 用 `Date.UTC` + `getUTC*`，宿主时区无关；年份固定补足 4 位。
- **选型必须跟随控件类型**（写错会产生畸形时间串）：
  `type="date"` / 已经是 `YYYY-MM-DD` 的值 → `dayBoundary(x, "start"|"end")`；
  `type="datetime-local"` / 已经是 `YYYY-MM-DDTHH:mm` 的值 → `toOffsetDateTime(x)`。
  排查时以对应 JSX 的 `type` 属性为准，不以变量名（`dateFrom` 之类）为准。

## 7. 风险与对策

| 风险 | 影响 | 控制 |
|---|---|---|
| 把纯日期字段当瞬时换算 | 体检/护理周期日期整体退一天 | `formatDate` 对 `YYYY-MM-DD` 原样透传；单测含 `formatDate("2026-07-01")` 断言 |
| 改写占位符或文案 | 既有 E2E 断言失败 | `empty` 参数保留 `-` / `—`；只改时间产生与呈现 |
| `datetime-local` 在非东八区浏览器上的解释 | 录入时间再错 | 输入文本一律按业务墙钟处理，提交始终显式带 `+08:00`，绝不用 `new Date(输入文本)` |
| 宿主时区相关实现（`getHours`/`toLocaleString`） | 换个时区又错 | 只用 `Intl.formatToParts`；三个宿主时区单测 |
| 大量机械改动引入遗漏 | 仍有 UTC 原文残留 | §6.4 全仓模式审计 + 独立评审复核 |
| 新测试文件被 `astro check` 纳入 | 构建失败 | 测试放 `apps/aceso/tests/`；必要时在 tsconfig `exclude`，不得删测试 |

### 9.2 评审结论（2026-09-29，独立评审角色）

**裁决：yes-with-caveats** — 可作为纯缺陷修复交付。评审独立复跑并**证实**调度者全部 5 条声称，
并自行追加 `tsc --noEmit`、`DATE` 列名 × `formatDateTime` 字段名全量交集、13 个 `datetime-local` 值来源追踪、
`client:load` 页 SSR/水合评估、E2E 唯一日期断言的字段溯源、后端 4 处解析契约核对。

评审确认无问题的关键项：

- 无遗漏的「原始瞬时灌进输入框」同类缺陷（13/13 输入值来源均合规）；
- 纯日期协议未被污染：`NursingPage` 时间线与 `ActivitiesPage` 统计仍发裸 `YYYY-MM-DD`，与后端 `LocalDate.parse` 一致；
- 可选字段「空则省略」语义全部保留；3 处 `new Date().toISOString()` 残留均为真瞬时；
- SSR/水合无风险（`client:load` 页无时间相关状态初值，且模块钉死业务时区使 SSR 与客户端恒等）；
- 占位符零变化（5 个原用 `—` 的组件逐调用点核对）；唯一 E2E 日期断言源自 `DATE` 字段，不受影响。
