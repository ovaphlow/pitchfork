## 1. 背景与用户决策

033 报告 A 项：账单生成后没有「作废 / 红冲」入口，错了只能「手工加项填负数」或「关账减免」抹平，不留痕、不关联原单。
用户在 033 计划第 6 节看到 A1（新增 `已作废` 状态）／A2（红字反向单）／A3（仅 metadata 留痕）三方案后裁定：

> **采用 A2（红冲／反向单）；其余口径按主流通用业务逻辑由实施方确定。**

因此本计划把 A2 的**业务口径与接口契约全部冻结**（第 2–4 节），两条车道不得自行改动。

## 2. 口径决策（主流通用做法，冻结）

红冲的通用语义：**永不修改、删除既有凭证；用一张金额取反的冲销凭证抵消它，并双向关联。**

1. **原单不动**：`total_amount`、`status`、`bill_items` 全部保留，不重算、不删除。
2. **红字单**：新建一张 `bills` 记录，`total_amount = −原单total_amount`（严格小于 0），
   `period_start/period_end` 复制原单，`status = 待缴费`，`reversal_of = 原单id`。
   - 为何 `待缴费`：全仓账务以“账单台账”为准 —— 欠费汇总 `PaymentService.summaryDueQuery` 对 `total_amount` **无状态过滤**求和，
     红字单自动抵减；关账路径 `BillService.outstandingBills` 与押金核销 `DepositOffsetService.targetBills` 都只取 `待缴费`，
     红字单进入后者也不会被核销（`signum() > 0` 判定排除负余额）。若红字单用 `已结清/已结算`，则上述两处不会抵减，必须额外改口径 —— 故用 `待缴费`。
3. **双向关联与留痕**：原单写 `reversed_at`（TIMESTAMPTZ）、`reversed_by`（认证主体）、`reversal_reason`；
   红字单写 `reversal_of`。**「谁在何时因为什么红冲了哪张单」四个问题全部可答。**
4. **可重算**：红冲后允许对同账期**重新生成**账单（这是用户报告的核心诉求）。因此
   `uq_bills_encounter_period` 降级为**部分唯一索引**：只约束「未被红冲的原单」，红字单不受该约束。
5. **红冲前提（保守，逐条独立报错）**：
   - 原单不存在 → 404；请求体含白名单外的键 / 缺少 `reason` / `reason` trim 后为空或 > 500 字 → 400；
   - 目标本身是红字单（`reversal_of IS NOT NULL`）→ 400 `cannot reverse a reversal bill`；
   - 原单已被红冲（`reversed_at IS NOT NULL`）→ 409；
   - 原单 `status <> 待缴费`（已结清/已结算 = 已发生收款或已关账）→ 409；
   - 该 encounter 已关账（`encounters.settled_at IS NOT NULL`）→ 409；
   - 原单已存在缴费记录（`payments.bill_id = 原单`）→ 409。
   - 以上全部**同一事务内**校验并写入；任一失败整体回滚，不留半成品。
6. **红字单与已红冲原单都不可再操作**（这正是「留痕 + 不重复出账」的落地点）：
   - 不可缴费：`PaymentService` 拒绝 `reversal_of IS NOT NULL` 或 `reversed_at IS NOT NULL` 或 `total_amount <= 0` 的账单；
   - 不可加项：`BillService.addItem` 拒绝上述两类账单；
   - 不可再红冲：见第 5 条；
   - 不可被押金核销：`DepositOffsetService.targetBills` 排除 `reversed_at IS NOT NULL`（红字单天然被负余额排除）。
7. **不做自动重算**：不自动生成替代账单；用户自行重新生成账期（第 4 条已放开唯一约束）。替代单与红字单之间**不**自动关联
   （避免猜测用户意图）；关联只在「原单 ↔ 红字单」之间建立 —— 这是红冲的标准形态。

## 3. 数据模型（V523 迁移，healthcare 当前最大版本为 V522）

```sql
ALTER TABLE healthcare.bills
    ADD COLUMN reversal_of     VARCHAR(32) REFERENCES bills(id),  -- 红字单指向被冲的原单
    ADD COLUMN reversal_reason VARCHAR,                           -- 红冲原因（写在原单上）
    ADD COLUMN reversed_by     VARCHAR,                           -- 红冲操作人（认证主体，写在原单上）
    ADD COLUMN reversed_at     TIMESTAMPTZ;                       -- 红冲时刻（写在原单上）
```

- 唯一性重排（关键，否则红字单与原单同账期必然冲突）：
  - `ALTER TABLE healthcare.bills DROP CONSTRAINT uq_bills_encounter_period;`
  - `CREATE UNIQUE INDEX uq_bills_encounter_period ON healthcare.bills (encounter_id, period_start, period_end) WHERE reversal_of IS NULL AND reversed_at IS NULL;`
    （语义：**每 encounter 每账期至多一张“有效原单”**；被红冲的原单让位，允许重算生成新单；红字单不参与该约束）
  - `CREATE UNIQUE INDEX uq_bills_reversal_of ON healthcare.bills (reversal_of) WHERE reversal_of IS NOT NULL;`
    （语义：**每张原单至多被红冲一次**）
- 不变量约束：
  - `CHECK (reversal_of IS NULL OR total_amount < 0)` —— 红字单必须为负；
  - `CHECK ((reversed_at IS NULL) = (reversed_by IS NULL) AND (reversed_at IS NULL) = (reversal_reason IS NULL))` —— 红冲三列同生同灭；
  - `CHECK (reversed_at IS NULL OR reversal_of IS NULL)` —— 红字单自身不能被标记为“已红冲”。
- 列注释用中文（沿用 V515/V519 风格）。

## 4. 接口契约（冻结，车道不得改）

```
POST /crate-api/healthcare/v1/bills/{id}/reversal
请求体（白名单严格，其它键 400）：{ "reason": "重复计费，按实际在院区间重算" }
成功 201：直接返回新建的红字单对象（与既有 single-response 口径一致），至少含
{
  "id": "<ULID>", "encounter_id": "...", "period_start": "YYYY-MM-DD", "period_end": "YYYY-MM-DD",
  "status": "待缴费", "total_amount": "-1234.00",
  "reversal_of": "<原单id>", "reversal_reason": null, "reversed_by": null, "reversed_at": null,
  "created_at": "...", "updated_at": "..."
}
失败：{ "error": "<英文可映射消息>" }，404 / 400 / 409 如上。
挂载：`HealthcareRoutes` 既有 `billAuthHandler` 块（与账单写操作同级；`libs/permissions` 无 bill 权限点，本轮不新建权限点）。
```

**响应新增字段（列表 `GET /bills`、详情 `GET /bills/{id}` 一并返回）**

| 字段 | 类型 | 含义 |
|---|---|---|
| `reversal_of` | `string \| null` | 本单是红字单时指向原单 |
| `reversal_reason` / `reversed_by` / `reversed_at` | `string \| null` | 本单是**已红冲的原单**时的原因/操作人/时刻 |
| `reversal_bill_id` | `string \| null` | 本单是**已红冲的原单**时，指向冲销它的红字单（服务端 `LEFT JOIN` 计算，只读） |

前端据此渲染「红冲单」/「已红冲（关联 #…）」标记并禁用两类的操作按钮；`total_amount` 为负时按负数与红色语义展示。

- **真库端到端**（`./scripts/aceso-test.sh`，唯一 DB 入口，只操作 `aceso_test@55432`）：
  1. 生成某账期账单（金额 A > 0）→ `POST .../reversal {reason}` → **201**，红字单 `total_amount = −A`、`reversal_of` 正确；
  2. 原单 `total_amount = A` **不变**、`status` **不变**、`reversed_at/reversed_by/reversal_reason` 已落库；
  3. 欠费汇总净额回到红冲前水平（净 0 或与原值一致）；
  4. 同账期**重新生成成功**（部分唯一索引生效），新单成为唯一有效原单；
  5. 对已红冲原单再次红冲 → **409**；对红字单红冲 → **400**；
  6. 红字单缴费 → **409/400**（不产生缴费流水）；红字单加项 → **400**，已红冲原单加项 → **400**；
  7. 有缴费记录的账单红冲 → **409**（先退款/冲正）。
