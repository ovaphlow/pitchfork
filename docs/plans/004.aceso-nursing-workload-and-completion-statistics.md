## 1. 决策与范围控制

本期实现“护理员工作量和计划完成率统计”的第一版：在既有护理工作台上，按日期范围汇总执行任务，并按执行人展示工作量和计划完成率。

统计只读取已经持久化的 `nursing_task_executions`。它不得在读取报表时调用
`ensureExecutionsForDateRange`、创建执行记录、修改状态或触发库存操作。历史日期的
缺失执行记录应通过既有 `POST /executions/generate` 显式回补，不能由统计接口隐式写入。

本期不新增表、Flyway 迁移、jOOQ codegen、后台任务或权限模型。现有
`planned_time`、`status`、`executor`、`task_id` 和任务的 `period_id` 已足以完成聚合；
只有在真实数据上的查询计划证明现有索引不足时，才另行提出最小范围的索引计划。

## 2. 目标

1. 护理主管可以查看一个日期范围内的整体任务量、应完成量、完成量、逾期量和计划完成率。
2. 护理主管可以按执行人比较同一范围内的工作量；未分配执行人的任务必须可见，不能静默丢失。
3. 统计口径与 003 的逾期口径一致，未来任务不会被误算为未完成。
4. 状态操作成功后，今日列表和统计区分别刷新，且任一请求失败不阻塞另一部分工作台。

## 3. 范围

- 返回全局汇总及按执行人分组的工作量、状态数量、逾期数量和计划完成率。
- 在 Aceso 现有“今日执行”视图顶部增加独立的统计区，可选择日期范围和执行人。
- 在执行开始、完成、跳过、取消成功后刷新当前统计结果。
- 为完成率计算、日期/筛选边界、聚合结果、路由校验和前端构建留下可复验验证证据。

### 3.2 明确不在本期范围

- 不实现跨日、周、月趋势图、排行榜、导出、独立统计页面或管理层仪表盘。
- 不统计按患者、任务类型、照护单元、药品/耗材金额、服务时长、上门签到或 SLA。
- 不以完成时间计算准时率、平均耗时或逾期时长；这些是后续质量指标，不能混同计划完成率。
- 不把统计结果写回执行记录、照护计划、考核、薪酬或绩效系统。
- 不改变现有 `/executions/today` 的筛选、分页、懒生成和逾期行为。

## 4. 统计口径

### 4.1 日期和参考时间

- `date_from`、`date_to` 使用 `YYYY-MM-DD`，均为闭区间的业务日期。
- 服务端将其转换为与既有 `todayExecutions` 相同的 UTC 日边界：
  `[date_from 00:00, date_to + 1 day 00:00)`。
- `date_from` 或 `date_to` 无法解析时返回 `400`；`date_from > date_to` 返回 `400`；
  单次范围最多 31 个日历日，超过时返回 `400`。
- 服务调用开始时只获取一次 `now: OffsetDateTime`。同一次响应的所有 `due_total`、
  `completed_due_total`、`overdue_total` 和完成率都必须使用这个相同的 `now`。

### 4.2 指标定义

所有计数都先应用日期范围、`period_id` 和 `executor` 筛选。执行记录没有
`planned_time` 时不属于统计范围。

| 字段 | 定义 |
|---|---|
| `scheduled_total` | 范围内的全部执行记录数，含未来任务。 |
| `pending_total` / `in_progress_total` / `completed_total` / `skipped_total` / `cancelled_total` | 范围内按当前状态计数；五项之和必须等于 `scheduled_total`。 |
| `due_total` | `planned_time < now` 的范围内记录数，不区分状态。未来计划不计入。 |
| `completed_due_total` | `status = COMPLETED AND planned_time < now` 的记录数。 |
| `overdue_total` | `status IN (PENDING, IN_PROGRESS) AND planned_time < now` 的记录数，与 003 完全一致。 |
| `completion_rate` | `completed_due_total / due_total * 100`，四舍五入到两位小数；`due_total = 0` 时为 `null`。 |

`SKIPPED` 和 `CANCELLED` 仍属于 `due_total`，但不属于 `completed_due_total`；它们会降低计划完成率，同时可由各自状态数量解释。`COMPLETED` 即使实际完成时间晚于计划时间，仍算完成；本期不计算准时率。

按执行人分组时，`executor = null` 是一个合法分组。响应保留 `executor: null`，前端显示“未分配”，使所有分组的 `scheduled_total` 之和与全局汇总相同。

## 5. API 契约

### 5.1 请求

```http
GET /crate-api/nursing/v1/executions/statistics?date_from=2026-07-27&date_to=2026-07-30&executor=01...&limit=100&offset=0
```

- `date_from`、`date_to` 必填。
- `period_id` 和 `executor` 为可选精确筛选，不接受隐式的“当前长者”条件。
- `limit`、`offset` 沿用列表语义，默认 `50`、`0`。它们只分页 `records`，不会改变汇总值。
- 本期前端只提供日期范围和执行人筛选；`period_id` 保留为后端契约和未来显式周期筛选的能力，不能悄悄复用长者详情当前选中的 `period`。

### 5.2 响应

分组结果仍使用项目统一的列表响应形状：

```json
{

      "executor": "01H...",
      "scheduled_total": 12,
      "pending_total": 2,

      "cancelled_total": 1,
      "due_total": 10,
      "completed_due_total": 7,
      "overdue_total": 3,
      "completion_rate": 70.0
    },
    {
      "executor": null,
      "scheduled_total": 2,
      "pending_total": 2,
      "in_progress_total": 0,
      "completed_total": 0,
      "skipped_total": 0,
      "cancelled_total": 0,
      "due_total": 1,
      "completed_due_total": 0,
      "overdue_total": 1,
      "completion_rate": 0.0
    }
  ],
  "meta": {
    "total": 2,
    "date_from": "2026-07-27",
    "date_to": "2026-07-30",
    "scheduled_total": 14,
    "pending_total": 4,
    "in_progress_total": 1,
    "completed_total": 7,
    "skipped_total": 1,
    "cancelled_total": 1,
    "due_total": 11,
    "completed_due_total": 7,
    "overdue_total": 4,
    "completion_rate": 63.64
  }

```

- `records` 按 `due_total DESC`、`scheduled_total DESC`、`executor ASC` 排序，未分配分组排在最后。
- `meta.total` 是符合筛选条件的执行人分组总数，含未分配分组；`meta` 中的指标忽略 `limit`、`offset`。
- 空范围返回 `records: []`、`meta.total: 0`，各数值指标为 `0`，`completion_rate: null`。
- 错误沿用 `{ "error": "<message>" }`，建议消息为：
  `date_from is required`、`date_to is required`、`invalid date format, expected YYYY-MM-DD`、
  `date_from must not be after date_to`、`date range must not exceed 31 days`。

## 6. 后端实施设计

### 6.1 `TaskExecutionService`

在 `TaskExecutionService.kt` 新增独立的 `executionStatistics(...)` 服务方法，不扩展已长达 128 行的 `todayExecutions(...)` 方法。

1. 在方法入口验证并固定 `now`，构造范围、周期和执行人共有条件。
2. 以 `nursing.nursing_task_executions e` 为主表，连接 `nursing.nursing_tasks t` 以支持 `t.period_id`；不要连接患者、耗材或身份服务。
3. 用固定数量的 jOOQ 聚合查询分别取得全局汇总和按 `e.executor` 分组结果。两个查询必须复用同一套筛选和 `now`，且不能按执行人循环查询。
4. 以 PostgreSQL `FILTER (WHERE ...)` 或等价 jOOQ 条件聚合计算第 4.2 节字段；不要加载明细后在内存计数。
5. 将汇总行映射为统一 JSON helper，令 `completion_rate` 只在 `due_total > 0` 时计算。把舍入和零分母处理抽为可直接单测的纯函数。
6. 统计查询不得调用执行记录生成、状态更新、耗材加载或 `loadConsumptionSummaryBatch`。本接口不能改变业务数据。

当前已有 `idx_exec_planned_time`、`idx_exec_status_planned` 和 `idx_task_period`。本期先复用它们；不为假设的报表负载新增迁移。若验收数据库上的 `EXPLAIN` 证明确有瓶颈，单独记录查询、数据量和候选索引，留给后续最小迁移决策。

### 6.2 `TaskExecutionRoutes`

1. 在 `/:id` 动态路由之前注册 `/statistics`，并保持与 `/today` 相同的尾部斜杠兼容行为。
2. 将统计参数解析提取为局部私有 helper 或复用 handler，避免再复制两段日期校验逻辑，尤其不能增加 `create()` 的分支复杂度。
3. 路由只负责参数格式、范围和分页校验；服务层负责聚合和业务口径。
4. 返回服务的 `{ records, meta }` 原样 JSON；非法参数使用 `NursingRoutes.respond(..., 400, ...)`，其他异常沿用 `respondError`。

### 6.3 Shared Aceso API

在 `ui-astro/packages/shared/src/aceso.ts` 中：

1. 新增 `NursingExecutionStatistics` 和带统计字段的 `NursingExecutionStatisticsPage` 类型；`executor` 明确为 `string | null`，`completion_rate` 为 `number | null`。
2. 新增 `listNursingExecutionStatistics({ date_from, date_to, period_id?, executor?, limit?, offset? })`，通过现有 `nursingQuery` 和 `request` 调用 `/nursing/v1/executions/statistics`。
3. 不在页面中手写 URL、`fetch`、token 或错误解析，也不改动 `listNursingTodayExecutions` 的参数和返回类型。

## 7. 前端实施设计

`NursingPage.tsx` 已是超过 1,300 行的工作台组件。新增统计功能应创建

### 7.1 面板行为

- 初始范围为本周周一至当天；两个日期输入都可修改，点击“查询”后才请求统计。
- 提供执行人下拉框，数据复用已加载的 `subjects`；“全部执行人”不传 `executor`。
- 查询以 `limit: 100` 获取分组，第一版不提供分组分页控件，但 API 必须支持分页。
- 顶部使用紧凑统计卡展示：计划任务、应完成、已完成、逾期、计划完成率。
- `completion_rate === null` 时显示“暂无应完成任务”，不能显示 `0%`。
- 以 `Table` 展示每个执行人分组：执行人、计划任务、应完成、已完成、逾期、完成率和状态摘要。执行人名称通过现有 `subjectMap` 映射，`null` 显示“未分配”。
- 面板有独立的 loading、error 和空态，不能覆盖或复用今日执行列表的 `actionError`。
- 面板首次加载、修改条件后的“查询”和状态操作成功后的刷新都使用同一个 `reload` 回调或版本号；统计请求失败不影响今日执行列表刷新，反之亦然。

### 7.2 与既有工作台的边界

- 将面板放在今日筛选卡和执行列表之前，保持当前“日期、状态、执行人、逾期”筛选及其 UI 行为不变。
- 今日执行的 `loadTodayExecutions` 与统计面板的加载函数保持独立。不要把统计数据塞进今日列表的 `meta`，也不要让统计面板隐式继承当前长者详情的 `period?.id`。
- 开始、完成、跳过、取消成功后，父组件同时触发今日列表刷新和统计面板刷新；失败时两个数据视图均保留上一次成功数据。
- 使用现有 Tailwind token、`Card`、`Badge`、`Table` 和 `Button`，不使用内联样式，也不新建页面或开发服务器。
