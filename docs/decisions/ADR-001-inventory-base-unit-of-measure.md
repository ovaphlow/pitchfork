# ADR-001：库存以最小可发放／可消耗单位记账

- 日期：2026-08-02
- 状态：提议中
- 决策范围：Aceso Inventory、Pharmacy、Nursing 的库存余额、库存流水、发药、耗材消耗、退回与成本核算。
- 相关计划：[002. Aceso 护理耗材使用与库存出库联动](../plans/002.aceso-nursing-supply-consumption-and-inventory-deduction.md)、后续 Pharmacy 发药与退药计划。

## 背景

当前库存与护理耗材方案以包装单位保存结存，在拆零使用时通过 `split_ratio` 折算包装数量。这能支持基础耗材扣减，但在以下场景会使库存事实难以阅读或校验：

- 药房按粒、片、支、瓶或毫升进行部分发药；
- 耗材按双、枚、片等实际使用单位消耗；
- 未给药或未使用部分需要退回库存；
- 包装规格变化、盘点、批次追溯与单位成本核算需要复现历史换算；
- 以 `0.5` 盒或 `0.0417` 箱表示余额会产生精度、尾差与操作歧义。

库存模型需要同时满足临床可操作性、账实可核对性和不可变流水审计，而不是只优化采购入库的整包录入体验。

## 决策

### 1. 基础记账单位

库存余额、可用量、锁定量、出入库明细、退回量和单位成本均以物资定义的**基础单位**记账。

基础单位定义为“最小可合法发放或可实际消耗的单位”，不机械等同于物理上可以无限拆分的最小单位：

| 物资类型 | 基础单位示例 | 说明 |
|---|---|---|
| 口服固体药品 | 粒、片、袋 | 按实际可发药单位记账；仅在物资明确允许时才可半片或更小分量。 |
| 注射药品 | 支、瓶、预充针 | 一支或一瓶一旦启封不能退回时，其本身是基础单位。 |
| 口服液、消毒液 | 毫升 | 仅在业务允许按体积分装或消耗时采用。 |
| 护理耗材 | 双、枚、片、支 | 以临床实际领用／消耗单位记账。 |
| 无菌组合包装 | 最小无菌包装 | 若拆包后不能安全回库，不得将内部单件作为基础单位。 |

每个物资只能有一个有效基础单位。存在流水后，基础单位不得直接修改；包装规格或单位策略变更必须通过受控换算或新物资档案处理。

### 2. 包装单位和换算

采购、入库、展示和盘点可使用整包单位，例如“盒、包、箱、瓶”。每种包装规格必须定义为到基础单位的正向、精确换算：

```text
1 盒阿莫西林 = 24 粒
1 箱阿莫西林 = 20 盒 = 480 粒
1 盒手套 = 50 双
```

系统在提交前把包装数量换算为基础数量；库存事实不使用“零点几盒”或“零点几箱”表示。系统应同时保存：

- 用户输入的原始数量与原始单位；
- 换算后的基础数量与基础单位；
- 提交当时使用的换算率快照；
- 使用的包装规格（若适用）。

历史流水一律使用自身快照回放，不能因物资档案日后调整包装规格而改变历史数量或成本。

### 3. 数量精度与拆分约束

所有库存数量使用 `NUMERIC`，禁止使用二进制浮点数。每个物资还必须定义可接受的基础数量精度：

- 粒、支、枚、片、双等默认只允许正整数；
- 液体可按物资配置小数位，例如 `0.001 mL`；
- 只有物资明确标记为可拆分时，才允许 `0.5` 片等非整数数量；
- 系统必须在换算后按该物资精度校验，不能静默四舍五入。

原有 `package_unit`、`split_unit`、`split_ratio` 等字段可在过渡期间作为包装与基础单位映射来源，但新模型应以语义明确的“基础单位 + 包装规格 + 换算率”表达；不再把“拆零”视为例外路径。

### 4. 成本、批次和不可变流水

- 库存结存按“仓库 + 物资 + 批次（可空）”保存基础数量与总成本。
- 单位成本是每一个基础单位的成本；入库时从包装成本换算，出库与退回时固化当时的成本快照。
- 批次、效期、物资状态、可用数量和并发锁定均按基础数量校验。
- 发药、耗材消耗、退药、报损和库存更正只能创建新的库存操作与明细；不得修改或删除既有确认流水。
- 退药必须引用原发药／领用明细，并校验未退数量。已给药、已启封、污染或报损的数量不得作为可用库存退回。

### 5. 医嘱、发药与护理执行的边界

药房发药与护理给药是两个独立业务动作：

```text
医嘱有效 → 药房发药／库存出库 → 护理执行给药 → 未使用药品退回或报损
```

- 只有有效的 `MEDICATION` 医嘱可以发药。
- 发药明细必须精确关联医嘱，并记录仓库、批次、基础数量、成本与操作者。
- 发药不得自动将护理任务或护理执行标记为完成；实际给药、拒服、漏服和浪费属于后续护理给药闭环。
- 医嘱停嘱、作废、离院或去世后禁止新的发药；已发未用数量依照退药／报损规则处理。

## 后果

### 正面影响

- 部分发药、部分领用、部分退回和盘点差异使用同一数量语言，账实容易核对。
- 批次追溯、效期控制、可用量判断、并发扣减和成本计算不必依赖小数包装数量。
- 前端可按“2 盒 + 5 粒”展示，但服务端始终使用一个确定的基础数量。
- 后续 Pharmacy、Nursing 与库存更正可共用同一事实账本。

### 代价与控制措施

- 物资档案需要维护包装规格、换算率和可拆分精度；校验与界面输入会更复杂。
- 基础单位不合理会直接影响临床操作，因此必须由业务人员确认药品和无菌耗材的可拆分规则。
- 包装变更会需要版本化或换算快照；禁止覆盖历史规格。
- 同一物资的不同批次与不同包装规格仍必须换算到同一基础单位后才能合并结存。

## 与现有计划的衔接

### 002：护理耗材与库存扣减

`002` 当前将包装单位数量作为结存与扣减口径，并用 `split_ratio` 支持拆零。该已实现方案不得通过修改旧 Flyway 迁移或重解释历史流水来强行改变语义。

后续由独立实施计划完成以下兼容演进：

1. 审计现有 `stocks`、库存操作明细和护理耗材关联的数量语义、换算率、历史数据量及 API 消费者。
2. 新增迁移，以显式基础单位字段和基础数量字段承载新的事实口径；历史数据保留原始包装数量、原始单位和换算快照。
3. 对可无歧义换算的数据回填基础数量；不能安全换算的数据保留历史标记并仅供只读展示，不能伪造余额。
4. 让新入库、出库和耗材消耗优先写入基础数量，同时在过渡期按 API 契约返回包装展示信息。
5. 在独立、可清理数据库上验证库存余额、成本、批次、幂等、并发和历史读取；不得用全局 Flyway `outOfOrder` 解决版本问题。

在上述迁移正式获批前，`002` 的现有行为仍是当前生产基线。

### 后续 Pharmacy 发药与退药计划

建议该计划以本 ADR 为前提，并至少落实以下验收要求：

1. 仅 `MEDICATION`、`ACTIVE` 的医嘱可创建发药；状态或终局收束冲突不产生任何库存写入。
2. 一张发药单可从一个或多个明确库存批次发出基础数量；库存不足、批次失效、重复提交或并发竞争必须全量回滚。
3. 发药单、发药明细、库存出库和医嘱关联共用同一事务；每条发药明细保存基础单位、原始包装输入和成本快照。
4. 全退与部分退均创建反向库存流水，累计退回不得超过原始可退数量；不修改历史发药明细。
5. 护理执行不会因发药自动完成，已给药数量不能作为可用库存退回。
6. PostgreSQL 集成测试和浏览器验收须在独立、可清理环境中覆盖整包入库、拆零发药、多批次、退药、终局阻断、幂等与并发。

## 非目标

- 本 ADR 不直接修改任何数据库、Flyway 迁移、生产服务、Shared API 或前端界面。
- 本 ADR 不决定采购订单、供应商、调拨、盘点、库存预警、收费结算、电子签名或审批流。
- 本 ADR 不授权把医嘱发药与护理实际给药合并为一个状态机。

## 后续动作

1. 由业务、开发、测试和评审确认基础单位定义、可拆分规则和成本精度。
2. 计划角色在确认后创建独立的 Inventory 单位模型演进计划，明确迁移、历史兼容、测试环境和数据清理要求。
3. 在该演进计划获验收后，再制定并实施 Pharmacy 发药与退药计划。
